---

## 0. 一句话定位

> **分析研究 = 一个可持续插入分析模块的工作台**。
> 框架解决三件事：模块怎么组织（导航）、模块长什么样（统一布局）、模块怎么接入（注册机制）。

---

## 1. 设计原则（5 条）

1. **注册即扩展**：新增一个分析 = 后端加一个模块 + 注册一条元数据；前端框架零改动（内置视图组件拼装）。
2. **跟踪与研究分流**：跟踪型（每日自动更新、看状态变化）与研究型（按需查参数、下钻明细）交互不同，不硬塞一个模板。
3. **结论先行**：每个模块首屏必须先给"结论数字/信号"，图表和明细都是论据——分析页不是数据页。
4. **口径透明**：每个指标旁边可查计算口径（tooltip/口径卡），与设计规范的指标定义一一对应，杜绝"数字怎么来的"黑箱。
5. **下钻闭环**：分析模块之间、分析→行情/概念/个股之间可跳转，延续"指数→行业→概念→个股"的下钻链。

---

## 2. 信息架构（两层）

```
分析研究（/analysis）
├── 总览页 /analysis            —— 跟踪型模块的卡片墙 + 研究型模块的入口目录
└── 详情页 /analysis/:moduleId  —— 单个分析模块的完整视图（AnalysisShell 容器）
```

### 2.1 总览页（默认落地页）

- **跟踪卡片区**：每个跟踪型模块一张摘要卡（名称 + 关键信号数字 + 一句状态 + 更新时间），
  例如「市场风向」卡显示：风偏分数 +6.5 / 剪刀差 +3.2pp / 状态标签「风偏升温」。
  每天 10 秒扫一眼，点卡片进详情。
- **目录区**：研究型模块按分组列出（名称 + 一句话说明），点击进详情。
- 分组固定五类（后续新增模块必须归入其一）：
  ① 市场风向 ② 板块与概念 ③ 个股基本面 ④ 资金与情绪 ⑤ 跟踪清单

### 2.2 详情页（AnalysisShell 统一容器）

所有模块共用同一骨架，**从上到下固定五段**：

| 段 | 内容 | 说明 |
|---|---|---|
| ① 标题区 | 模块名 + 口径说明（? tooltip）+ 数据截至时间 + 所处分组面包屑 | 截至时间来自物化表 MAX(trade_date)，滞后会变琥珀色 |
| ② 参数区 | 周期/日期等参数 chips（NSelect/DatePicker），改变即刷新 | 参数 schema 由模块元数据声明 |
| ③ 结论区 | 2~4 个 KPI 结论卡（大数字 + 状态词），**金色仅用于系统产出的亮点信号** | 红涨绿跌仅出现在行情数字 |
| ④ 主视图 | 模块主图表（从内置视图组件中选 1~2 个拼装） | 见 §4 视图组件清单 |
| ⑤ 明细区 | 可展开的数据表 + 下钻按钮（跳行情/概念/个股） | 表格列由模块声明 |

## 3. 扩展机制（框架核心）

### 3.1 后端：模块注册表（registry）

- 新表 `analysis_registry`（或先配置文件）声明每个模块的元数据：

```json
{
  "module_id": "market-wind",
  "name": "市场风向",
  "group": "市场风向",
  "kind": "track",              // track=跟踪型 / research=研究型
  "desc": "六组指数风向 + 大小盘剪刀差 + 风偏分数",
  "api": "/api/analysis/market-wind",
  "params_schema": [ {"key":"window","type":"select","options":[5,20,60],"default":20} ],
  "views": ["group-heat-bar", "size-gradient", "wind-gauge", "dual-line"],
  "drilldown": [ {"label":"看K线","target":"market"} ]
}
```

- API 约定：`GET /api/analysis/registry`（总览页目录用）+ `GET /api/analysis/<module_id>`（模块数据，统一返回 `{as_of, kpis[], main_view, detail_table}` 骨架）。
- **新增模块的标准动作**：`app/analysis/` 加计算模块 → registry 注册 → 完毕。后端到前端一条链，无散落改动。

### 3.2 前端：组件注册表 + 内置视图库

- 路由 `/analysis/:moduleId` 动态匹配；`viewsById` 映射表把 module_id 指到对应视图组件（缺失则显示"模块开发中"占位）。
- **内置视图组件**（先建 6 个，覆盖绝大多数分析形态，新模块优先复用）：

| 组件 | 形态 | 适用 |
|---|---|---|
| `KpiCards` | 2~4 张结论大数字卡 | 所有模块的结论区 |
| `GroupHeatBars` | 分组水平热力条（红涨绿跌） | 六组收益、行业对比 |
| `SizeGradient` | 有序梯度条（超大盘→微盘） | 市值风格、规模对比 |
| `DualLineTrend` | 双轴/双线时序 + 拐点标注 | 剪刀差、风偏分数等轮动序列 |
| `RankTable` | 排行表（可切区间/正序倒序） | 股息率、概念、YTD 等排行型 |
| `DrillLink` | 下钻按钮组（K线/概念/个股跳转） | 明细区统一交互 |

## 4. 首发模块：市场风向（P0）

### 4.1 数据层：物化表 `market_style_daily`（每日一行）

挂在 `index_market_sync`（18:30）之后 18:45 跑，纯库内 SQL 计算、幂等重建当日行：

| 字段组 | 字段 | 口径 |
|---|---|---|
| 六组收益 | `ret_bench_20/60, ret_size_20/60, ret_tech_20/60, ret_sent_20/60, ret_div_20/60, ret_pol_20/60` | 组内等权 N 日收益(%) |
| 剪刀差 | `scissors_20, scissors_60` | (中证1000+中证2000 等权) − (上证50+沪深300 等权) N 日收益 |
| 风偏 | `risk_appetite_20` | 科技成长组 − 股息防守组（20 日） |
| 情绪 | `sentiment_20` | 证券公司 − 中证全指（20 日超额） |
| 政策 | `policy_excess_20` | 中证全指房地产 − 中证全指（20 日超额） |
| 大势 | `bench_pos_pct` | 中证全指在近 250 日高低区间的分位(%) |

**市场宽度（v0.3 新增，2026-09-14）** —— 源 `stock_market_daily` 个股日线，**pandas 增量计算**（非 SQL 窗口函数，见 §9 性能说明）：

| 字段组 | 字段 | 口径 |
|---|---|---|
| 涨跌家数 | `breadth_total / breadth_up / breadth_down / breadth_up_ratio` | 当日有收盘价个股数及其涨跌分布；占比=上涨/总数% |
| 情绪极值 | `limit_up / limit_down` | 涨幅≥9.8%（主板）/ ≥19.8%（创业板 30x、科创板 68x，按代码前缀判定）近似口径 |
| 均线参与度 | `above_ma20_pct / above_ma60_pct` | 收盘站上各自 MA 的个股占比%；MA60 分母为有 60 日历史的个股 |
| 新高新低 | `new_high60 / new_low60 / hl_diff60` | 创 60 日新高/新低家数及其差（市场内部强弱） |
| 腾落线 | `breadth_adl` | ADL 全史累计 Σ(上涨−下跌)，**必须基于合并后完整序列累计**，保证跨块连续 |

**量能（v0.3 新增，2026-09-14）** —— 与宽度同源于同一次取数（零额外成本）：

| 字段组 | 字段 | 口径 |
|---|---|---|
| 成交额 | `market_amount` | 全市场个股 `amount` 求和（亿元） |
| 放缩量 | `amount_ratio_20` | 成交额 / 近 20 日均值 × 100%（>100 放量，<100 缩量） |

> 好处：口径版本化可回测、前端 O(1)、可加 DQ 规则（freshness + 行数 + 宽度非空/越界/自洽）、未来直接喂 AI 生成日报。
> 取数依赖覆盖索引 `idx_breadth_cover (stock_code, trade_date, close, change_pct)`，EXPLAIN 走 `Using index for skip scan` 全索引覆盖免回表；由 `scripts/seed_indexes.py` 创建（索引唯一事实来源）。

### 4.2 视图层（AnalysisShell 拼装）

- ③ 结论区 KPI：`风偏分数`（正=进攻/负=防守，金色高亮极值）+ `大小盘剪刀差` + `大势位置`（分位%）+ **`情绪温度` / `政策超额`**（v0.3 补白算指标）；每张 KPI 附**近一年分位**与 **z-score**（偏离均值几个标准差），跨期可比
- ④ 主视图：
  - `GroupHeatBars`（六组 20 日收益热力条，**点击下钻**到该组明细）+ `DualLineTrend`（剪刀差 & 风偏分数双线，近 1 年，**叠加轮动区间底色带**：小盘占优=金、大盘占优=蓝，过滤 <3 天的翻转噪声）
  - **`BreadthPanel`**（v0.3 新增）：涨跌分布条 + 四格明细（涨停/跌停、站上 MA20%、站上 MA60%、60 日新高−新低）+ 腾落线
  - **量能条**（v0.3 新增）：全市场成交额 + 放缩量 ratio（>100 放量红、<100 缩量绿，仅数字语义用红绿）
  - **`HeatMatrix`**（v0.3 新增）：六组 × 时间（12 段等分回看窗口）热力矩阵，行点击下钻
- ⑤ 明细区：六组内 21 只指数列表（最新涨跌/20 日收益/近一年分位），行内下钻 K 线；支持按组**过滤下钻**（`NTabs`）
- ⑥ **历史回放**（v0.3 新增）：`NDatePicker` 选 as_of 锚点，全链路只取 `trade_date <= as_of`，回放模式不报滞后（数据天然落后）
- 附：状态词规则（首版简单化）——风偏分数 >0 且近 5 日走扩 =「风偏升温」；<0 且收敛 =「防守松动」；其余 =「均衡震荡」
- 配色纪律（「蓝骨金魂」）：涨=红 `#EF232A` / 跌=绿 `#14B143` **仅用于行情语义数字**；占比/健康度=主色 `#185FA5`；金色 `#C9A227` 仅用于极值标记（≤10%/≥90% 分位）；区间底色带用金/蓝（表风格占优方，非涨跌）

## 9. 市场风向模块增强记录（2026-09-14，四批）

> 缘起：用户就"市场风向"主题征集优化建议，共列 16 项分四批全选落地。
> 原则：**不牺牲 P0 的"口径版本化可回测"**——所有新增指标一律物化落表，前端只读不算。

| 批次 | 主题 | 落地内容 |
|---|---|---|
| **1** | KPI 扩充与交互 | 补 `sentiment_20` / `policy_excess_20` 两个「白算」指标入 KPI；每张 KPI 加**近一年分位**（金色标记 ≤10% / ≥90% 极值）与 **z-score**；加**滞后提示**（数据落后交易日数）；KPI 卡可**锚点下钻** |
| **2** | 市场宽度 | 物化表加 **12 列**：`breadth_total/up/down/up_ratio/adl`、`limit_up/down`、`above_ma20_pct/above_ma60_pct`、`new_high60/new_low60/hl_diff60`；新增 `BreadthPanel.vue` 视图 |
| **3** | 量能 + 标准化 | 物化表加 **2 列**：`market_amount`、`amount_ratio_20`（放缩量）；`_standardize()` 对 6 组收益/KPI 统一算近 250 日分位 + z-score；新增量能条 |
| **4** | 结构性增强 | `HeatMatrix.vue`（六组×12 段热力矩阵）；`DualLineTrend` 加轮动**区间底色带**（`_sign_bands` 过滤 <3 天翻转）；`NDatePicker` **历史回放**（全链路 `as_of`）；点热力条/矩阵行 → 明细 `NTabs` **过滤下钻链** |

**性能决策（重要，勿回退）**：宽度/量能**不得**用 SQL 窗口函数——`stock_market_daily`（1813 万行/2.2GB）上 3→4 个窗口耗时从 8.2s 跳到 62.1s（会话缓冲 `tmp_table_size` 33MB 导致窗口结果集落盘）。改用 **pandas 增量**（6.5s 抓数 + 3.3s 计算 ≈ 10s/日），全史回填分块（2 年/块）+ 每块 `del raw; gc.collect()` 防内存劣化，首次全史约 3~5 分钟。

**字段口径**：宽度与量能同源同一次取数（`_fetch_raw` 多带 `amount` 列），`MARKET_COLS = BREADTH_COLS + VOLUME_COLS` 一次合并一次写入。

**DQ**：新增 3 条规则 `style_breadth_notnull`（宽度列非空率）/ `style_breadth_range`（占比越界）/ `style_breadth_hl`（`hl_diff60` 自洽）——须以种子脚本 `seed_dq_rules.py` 为准。

**已知约束**：表刚加列时存在"有行但宽度全 NULL"的过渡态，增量门控须过滤 `breadth_up_ratio IS NOT NULL`，新增派生列后以 `full_refresh=True` 强制全量重算（否则历史永远空）。
