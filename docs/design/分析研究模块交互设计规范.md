## 1. 数据比较框架与设计原则

### 1.0 第一原则：数据用来比较才有意义（2026-09-15 确立）

> **单个数字不是信息，只是噪声；只有放进一个比较关系里，它才成为信号。**
>
> 「今日成交 1.57 万亿」说明不了任何问题——是高是低？比昨天多还是少？在近一年处于什么位置？跟谁比？
> **没有参照物的数字不上线。** 这条原则先于本规范其余所有条款，用于**设计**（先问「跟谁比」）也用于**验收**（数字旁边有没有参照物）。

**五类参照系** —— 任何指标至少要落进一类，落不进的不予接入视图：

| # | 比较类型 | 参照物 | 回答的问题 | 本项目已落地实例 | 待补实例 |
|---|---|---|---|---|---|
| ① | **同类横比** | 同层级的不同对象 | 谁强谁弱？ | 六组指数 20 日收益、大小盘五档梯度、**申万行业 31/131 排行、概念 375 排行**（v0.6） | — |
| ② | **自身纵比** | 自身的历时序列 | 现在算不算极端？ | `pct` 近 250 日分位、`z`、`adj` 风险调整、**各印证维度的 20 日变化分位** | 估值分位、两融余额分位 |
| ③ | **基准超额** | 恰当的基准（非绝对收益） | 是真强，还是水涨船高？ | `sentiment_20`（券商−全指）、`policy_excess_20`（地产−全指）、**行业相对 `ret_bench_20` 超额**（v0.6） | 概念口径超额 |
| ④ | **交叉印证** | 另一个独立维度 | 有没有被别的口径证实？ | **六维全套（v0.6）**：杠杆 风偏×两融 / 股债 大势×10Y / 股商 周期组×商品基差 / 口径 指数×概念 / 微观 涨跌停×换手率 / 量价 大盘×量比 | 海外（恒生/纳指）、汇率、Shibor |
| ⑤ | **结构分解** | 内部构成 | 是普涨，还是少数拉动？ | 涨跌家数、60 日新高新低、均线参与度、**行业/概念上涨占比 + 离散度 + 首尾差**（v0.6） | 换手率结构、涨停/连板结构 |

**比较的最高级用法是「背离」** —— 两个本该同向的维度不同向，才是可交易的信息：

| 背离 | 读法 | 落地状态 |
|---|---|---|
| **指数 × 个股** | 指数涨而宽度差 = 少数权重股拉动的虚涨 | ✅ 已具备（`ret_bench_20` × `breadth_up_ratio`） |
| **量价** | 涨而缩量 = 虚涨；跌而缩量 = 抛压衰竭 | ✅ **v0.6 已具备**（大盘 20 日收益 × `amount_ratio_20`，成对判据 + 死区方向法） |
| **股债** | 利率创新低而股市创新低 = 流动性未传导 | ✅ **v0.6 已具备**（`cn_bond_10y` × `bench_pos_pct`；无估值分母故**不做 ERP**） |
| **股商** | 商品基差走强而周期股走弱 = 实体改善未被股价反映 | ✅ **v0.6 已具备**（`futures_spot_price` 基差 z × 对应风格组收益） |
| **杠杆** | 风偏骤降而两融仍处高位 = 杠杆盘固执 | ✅ **v0.6 已具备**（`risk_appetite_20` × 两融余额） |
| **口径** | 指数口径与概念口径打架 = 没有一致的市场叙事 | ✅ **v0.6 已具备**（六组中位 × 概念中位；两模块各自复用） |

**三条硬性约束**（写进评审清单）：

1. **无参照物不上线**：新增任何 KPI/指标，必须同时声明它的参照物（分位 / 超额 / z / 同类 / 基准），否则不予接入视图层。
2. **口径随响应下发**：口径说明由后端下发（如 `ADJ_NOTE` / `adj_note`），前端**只透传不手抄**——避免前后端各写一份而漂移（§4.2 已实践）。
3. **优先落地「能产生背离信号」的指标对**：单个指标只能描述状态，成对指标才能给出判断；评审时优先给「成对且可比」的方案排队。

### 1.1 设计原则（5 条）

1. **注册即扩展**：新增一个分析 = 后端加一个模块 + 注册一条元数据；前端框架零改动（内置视图组件拼装）。
2. **跟踪与研究分流**：跟踪型（每日自动更新、看状态变化）与研究型（按需查参数、下钻明细）交互不同，不硬塞一个模板。
3. **结论先行**：每个模块首屏必须先给"结论数字/信号"，图表和明细都是论据——分析页不是数据页。
4. **口径透明**：每个指标旁边可查计算口径（tooltip/口径卡），与设计规范的指标定义一一对应，杜绝"数字怎么来的"黑箱。
   （2026-09-19：**总览页卡片墙 + 详情页两处统一落地**，共用 `KpiHint.vue`；此条此前只在详情页兑现，卡片墙一直缺入口，见 §14）
5. **下钻闭环**：分析模块之间、分析→行情/概念/个股之间可跳转，延续"指数→行业→概念→个股"的下钻链。

## 2. 信息架构（两层）

```
分析研究（/analysis）
├── 总览页 /analysis            —— 跟踪型模块的卡片墙 + 研究型模块的入口目录
└── 详情页 /analysis/:moduleId  —— 单个分析模块的完整视图（AnalysisShell 容器）
```

### 2.1 总览页（默认落地页）

- **跟踪卡片区**（v1.1 拆卡 + v1.2 分组）：每模块拆 3 张卡（各答一件事），**同模块的 3 张卡聚为一组**，
  组标题承担领域名 ⇒ 卡片名只留**短名**（「位置」而非「市场风向 · 位置」）。

  **卡内信息分三层**（自上而下），每层各司其职、**互不重复**：

  | 层 | 内容 | 回答什么 | 来源字段 |
  |---|---|---|---|
  | 判读条 | 一句结论（✦/▲ 符号 + 三态底色） | **判断与影响** —— 现在什么状态、意味着什么 | `verdicts[q].headline`(+`detail`) |
  | KPI 区 | N 个大数字 + 状态词 + 分位刻度 | **读数与分位** —— 具体多少、在历史什么位置 | `kpis[]`（按 `card_rank` 挑） |
  | 组标题 | 领域名（🧭 市场风向 / 🌍 跨市场对照 …） | **我在看哪个领域** | 该卡 `detail` 指向的详情模块 `name` |
  | 卡片右上角 | `截至 MM-DD` | **这份读数有多新** | 响应里的 `as_of` |
  | 卡片副标题 | 本卡问的那句话（「我们相对外面强还是弱」） | **这张卡在答什么** | `question_text` |

  卡片宽度按**上墙论据数**分三档（`card_span`：`narrow`=1 / `half`=2~3 / `full`=≥4）；
  容器列数 = 组内各卡 span 之和（CSS 变量 `--ao-cols`）⇒ **每行必定铺满、右侧不留空档**。
  判读条文案必须满足**四判据 V1~V4**（见 §15.2，可 lint 回归）。
  每天 10 秒扫一眼，点卡片进详情。
- **目录区**：研究型模块按分组列出（名称 + 一句话说明），点击进详情。
- **领域 = 分组**（v1.3 收敛）：领域名由 `detail` 模块的 `name` 唯一确定，并同步写进 registry 的
  `group` 字段（取值 = 该模块所属领域：track 卡 = 其 `detail` 的 `name`，detail 模块 = 自身 `name`）。
  当前 5 个领域（**按展示顺序**）：💧 **货币流动性** / 🧭 市场风向 / 🔀 板块轮动 / 🌍 跨市场对照 / 🌡️ 资金温度。
  （💧 于 2026-09-25 由「钱贵不贵」更名而来 —— 原名只覆盖价格一维，见 §16；同日并提到**首位**）
  新增模块必须归入其一；**领域顺序的唯一来源 = registry 里条目的先后**：卡片墙组顺序
  （= 组内首个 track 卡的出现顺序）与研究目录分区顺序都从它派生，不是硬编码，前端不得另立第二套顺序。

> ✅ **「两套组」已于 v1.3 收敛为一套（2026-09-25）** —— 原状态与根因（实测留痕）：
> 注册表的 `group` 当时是**另一套** taxonomy（固定五类：市场风向 / 板块与概念 / 个股基本面 /
> 资金与情绪 / 跟踪清单，后两类**从未有模块使用**），而卡片墙分组由 `detail` 聚合而来，
> 两者**只在「市场风向」上恰好同名**（`sector-rotation-*` 标「板块与概念」、`cross-market-*` 标「市场风向」）；
> 且 5 个 detail 里有 1 个被错标（`cross-market` 自身是「跨市场对照」这个领域，却标了 `市场风向`）
> ⇒ **详情页头部顶着错的领域标签**（用户可见缺陷）。
> 处置：`group` 语义收敛为「所属领域」，改写 16 处取值；前端 `GROUP_ORDER` 改为从 registry 派生；
> 详情页 `NTag` 改为仅在 `group !== name` 时渲染。完整证据见 **§15.8.1**。

### 2.2 详情页（AnalysisShell 统一容器）

所有模块共用同一骨架，**从上到下固定五段**：

| 段 | 内容 | 说明 |
|---|---|---|
| ① 标题区 | 模块名 + 口径说明（? tooltip）+ 数据截至时间 + 所处分组面包屑 | 截至时间来自物化表 MAX(trade_date)，滞后会变琥珀色 |
| ② 参数区 | 周期/日期等参数 chips（NSelect/DatePicker），改变即刷新 | 参数 schema 由模块元数据声明 |
| ③ 结论区 | 2~4 个 KPI 结论卡（大数字 + 状态词），**金色仅用于系统产出的亮点信号** | 红涨绿跌仅出现在行情数字 |
| ④ 主视图 | 模块主图表（从内置视图组件中选 1~2 个拼装） | 见 §4 视图组件清单 |
| ⑤ 明细区 | 可展开的数据表 + 下钻按钮（跳行情/概念/个股） | 表格列由模块声明 |

## 3. 扩展机制（框架核心）

### 3.1 后端：模块注册表（registry）

- 新表 `analysis_registry`（或先配置文件）声明每个模块的元数据：

```json
{
  "module_id": "market-wind",
  "name": "市场风向",
  "group": "市场风向",
  "kind": "track",              // track=跟踪型 / research=研究型
  "desc": "六组指数风向 + 大小盘剪刀差 + 风偏分数",
  "api": "/api/analysis/market-wind",
  "params_schema": [ {"key":"window","type":"select","options":[5,20,60],"default":20} ],
  "views": ["group-heat-bar", "size-gradient", "wind-gauge", "dual-line"],
  "drilldown": [ {"label":"看K线","target":"market"} ]
}
```

- API 约定：`GET /api/analysis/registry`（总览页目录用）+ `GET /api/analysis/<module_id>`（模块数据，统一返回 `{as_of, kpis[], main_view, detail_table}` 骨架）。
- **新增模块的标准动作**：`app/analysis/` 加计算模块 → registry 注册 → 完毕。后端到前端一条链，无散落改动。

### 3.2 前端：组件注册表 + 内置视图库

- 路由 `/analysis/:moduleId` 动态匹配；`viewsById` 映射表把 module_id 指到对应视图组件（缺失则显示"模块开发中"占位）。
- **内置视图组件**（先建 6 个，覆盖绝大多数分析形态，新模块优先复用）：

| 组件 | 形态 | 适用 |
|---|---|---|
| `KpiCards` | 2~4 张结论大数字卡 | 所有模块的结论区 |
| `GroupHeatBars` | 分组水平热力条（红涨绿跌） | 六组收益、行业对比 |
| `SizeGradient` | 有序梯度条（超大盘→微盘） | 市值风格、规模对比 |
| `DualLineTrend` | 双轴/双线时序 + 拐点标注 | 剪刀差、风偏分数等轮动序列 |
| `RankTable` | 排行表（可切区间/正序倒序） | 股息率、概念、YTD 等排行型 |
| `DrillLink` | 下钻按钮组（K线/概念/个股跳转） | 明细区统一交互 |

## 4. 首发模块：市场风向（P0）

### 4.1 数据层：物化表 `market_style_daily`（每日一行）

计算任务 `market_style_sync` cron **`30 21 * * 0-4`（每工作日 21:30，仅兜底）**，纯库内 SQL 计算、幂等重建当日行。
**主触发已改为链式**：`stock_daily_incr` 成功后由调度器自动接力（`scheduler.CHAIN_NEXT`），固定时刻仅在当日链式未跑成时才执行。

> ⚠️ **排期契约（2026-09-17 二次修正，血泪教训）**：本表的输入是**个股日线**，而 `stock_daily_incr`
> （19:20 起跑）常态耗时 **15~52 分钟** —— 因此**任何早于「日线完成」的固定时刻都会读到半量日线**。
> 排期演进：`18:45`（挂指数同步后）→ `20:05` → **链式触发（固定时刻降为兜底）**。
> 2026-09-16 实测：`market_style_daily[9/16]` 的宽度类字段全 NULL → `cross_checks` 的
> **`micro`（微观结构）与 `pxvol`（量价）两项当场退化为「数据缺失」**（`nodata:2`）。
> 2026-09-17 实测：20:05 班次在日线只跑了一半时「成功」执行（写 5254 行实为**上一交易日**数据），
> 证明「把固定时刻往后挪」治标不治本 —— 日线耗时本身在 15~52 分钟间波动，任何固定值都可能赌输。
> 保留**日线充分性护栏**兜底：当日行数不足上一交易日 **90%** 时，计算上界退回上一交易日
> （`_safe_max_date()`）——**宁可停在上一交易日，不写半量数据**；此时 `run_detail` 写入
> `stale_upper_bound` 显式标注，不再静默 success。
> 同源问题在 `market_current_sync` 亦有（见 §13）。

| 字段组 | 字段 | 口径 |
|---|---|---|
| 六组收益 | `ret_bench_20/60, ret_size_20/60, ret_tech_20/60, ret_sent_20/60, ret_div_20/60, ret_pol_20/60` | 组内等权 N 日收益(%) |

| 政策 | `policy_excess_20` | 中证全指房地产 − 中证全指（20 日超额） |
| 大势 | `bench_pos_pct` | 中证全指在近 250 日高低区间的分位(%) |

**风险调整（v0.4 新增，2026-09-15）** —— 修正「两条腿波动率不对称」造成的尺度漂移：

| 字段组 | 字段 | 口径 |
|---|---|---|
| 剪刀差风险调整 | `scissors_adj20` | `scissors_20` ÷ 其自身近 250 日滚动标准差 |
| 风偏风险调整 | `risk_appetite_adj20` | `risk_appetite_20` ÷ 其自身近 250 日滚动标准差 |

> **为什么需要**：两条腿的波动率并不对称——实测 σ(科技成长)/σ(股息防守) 中位 **2.21 倍**，
> 于是差值波动被高波动腿主导，「同样的 −12pp」在高波动期与低波动期含义完全不同：
> 2024 初小盘股灾 diff −16.12 / σ 4.89 → adj **−3.26**（极罕见）；当前 diff −13.49 / σ 12.16 → adj **−1.12**（常规）。
> **三条口径要点**：
> ① **刻意不减滚动均值**——减了就退化成「250 日排位」，与已有的 `pct` 分位重复，且会把趋势误当偏离；
> ② σ 恒正 → `adj` 必与原差值同号（数学必然，故 DQ 用 `style_adj_sign` 作 critical 校验）；
> ③ 中性点 **0 = 两腿同收益**，±1 = 偏离自身一个典型波动单位，可跨期比较（实测全史 mean 0.084 / sd 1.095）。
>
> **与 `pct` 的分工**：`pct` 答「在近一年排第几」（纯相对排位、受区间选择影响）；
> `adj` 答「偏离自身风险尺度几个单位」（含幅度、不受「近一年恰好是牛是熊」影响）。两者并列展示、互为参照。
> 覆盖区间：`risk_appetite_adj20` 2020-04-30 起（受科创50 等新指数上市限制）、`scissors_adj20` 2014-04-30 起。

**市场宽度（v0.3 新增，2026-09-14）** —— 源 `stock_market_daily` 个股日线，**pandas 增量计算**（非 SQL 窗口函数，见 §9 性能说明）：

| 字段组 | 字段 | 口径 |
|---|---|---|
| 涨跌家数 | `breadth_total / breadth_up / breadth_down / breadth_up_ratio` | 当日有收盘价个股数及其涨跌分布；占比=上涨/总数% |
| 情绪极值 | `limit_up / limit_down` | 涨幅≥9.8%（主板）/ ≥19.8%（创业板 30x、科创板 68x，按代码前缀判定）近似口径 |
| 均线参与度 | `above_ma20_pct / above_ma60_pct` | 收盘站上各自 MA 的个股占比%；MA60 分母为有 60 日历史的个股 |
| 新高新低 | `new_high60 / new_low60 / hl_diff60` | 创 60 日新高/新低家数及其差（市场内部强弱） |
| 腾落线 | `breadth_adl` | ADL 全史累计 Σ(上涨−下跌)，**必须基于合并后完整序列累计**，保证跨块连续 |

**换手率（v0.6 新增，2026-09-15）** —— 源 `stock_market_daily.turnover_ratio`，随宽度同一次取数：

| 字段组 | 字段 | 口径 |
|---|---|---|
| 换手率中位 | `turnover_med` | 全市场个股换手率**中位数**（%）。**必须取中位数**：源列存在 max 20.27 异常值，均值被污染近 10 倍 |

> **为什么不实时查**：按 `trade_date` 查 `turnover_ratio` 是非索引列 → 随机回表，**单日 15 秒**；
> 物化后随 `market_style_daily` 一行取到（O(1)）。这正是「微观结构」印证（涨跌停 × 换手率）能上线的前提。
> ⚠️ **源列单位漂移（v0.6 修）**：`turnover_ratio` 在 **2025-09 中旬**从百分数（`2.0` = 2%）切换为小数（`0.02` = 2%），
> **相差 100 倍**。采集器按日判断口径（阈值 `TURNOVER_FRACTION_MAX=0.3`，小数口径 ×100），
> 已入库历史段用 `UPDATE … SET turnover_med = turnover_med/100 WHERE turnover_med >= 30` 修正（5019 行）。
> 修正后全史区间 **0.46% ~ 8.59%**，分布合理；DQ 加 `style_turnover_range`（critical）兼作单位漂移守护。

**量能（v0.3 新增，2026-09-14）** —— 与宽度同源于同一次取数（零额外成本）：

| 字段组 | 字段 | 口径 |
|---|---|---|
| 成交额 | `market_amount` | 全市场个股 `amount` 求和（亿元） |
| 放缩量 | `amount_ratio_20` | 成交额 / 近 20 日均值 × 100%（>100 放量，<100 缩量） |

> 好处：口径版本化可回测、前端 O(1)、可加 DQ 规则（freshness + 行数 + 宽度非空/越界/自洽）、未来直接喂 AI 生成日报。
> 取数依赖覆盖索引 `idx_breadth_cover (stock_code, trade_date, close, change_pct)`，EXPLAIN 走 `Using index for skip scan` 全索引覆盖免回表；由 `scripts/seed_indexes.py` 创建（索引唯一事实来源）。

**性能决策（重要，勿回退）**：宽度/量能**不得**用 SQL 窗口函数——`stock_market_daily`（1813 万行/2.2GB）上 3→4 个窗口耗时从 8.2s 跳到 62.1s（会话缓冲 `tmp_table_size` 33MB 导致窗口结果集落盘）。改用 **pandas 增量**（6.5s 抓数 + 3.3s 计算 ≈ 10s/日），全史回填分块（2 年/块）+ 每块 `del raw; gc.collect()` 防内存劣化，首次全史约 3~5 分钟。

**字段口径**：宽度与量能同源同一次取数（`_fetch_raw` 多带 `amount` 列），`MARKET_COLS = BREADTH_COLS + VOLUME_COLS` 一次合并一次写入。

**DQ**：新增 3 条规则 `style_breadth_notnull`（宽度列非空率）/ `style_breadth_range`（占比越界）/ `style_breadth_hl`（`hl_diff60` 自洽）——须以种子脚本 `seed_dq_rules.py` 为准。

**已知约束**：表刚加列时存在"有行但宽度全 NULL"的过渡态，增量门控须过滤 `breadth_up_ratio IS NOT NULL`，新增派生列后以 `full_refresh=True` 强制全量重算（否则历史永远空）。

> 复核后确认原口径站得住（做差剥离 beta、组内等权要求全员有值、分位补救跨期不可比），
> 但识别出一处**真实缺陷**——两条腿波动率不对称导致差值尺度漂移。

### 10.1 问题：为什么需要风险调整

`风偏分数 = ret_tech_20 − ret_div_20` 是两条腿的收益差，但两条腿的波动率并不对等：

| 窗口 | σ(科技成长) 均值 | σ(股息防守) 均值 | σ 比（中位） |
|---|---|---|---|
| 120 日 | 8.25 | 4.52 | 2.28 |
| **250 日（采纳）** | **8.88** | **4.92** | **2.21** |
| 500 日 | 9.30 | 5.34 | 2.18 |

差值波动因此被高波动的科技端主导，「同样是 −12pp」在不同波动环境下并不可比：

| 时期 | 原始差值 | σ_diff | 风险调整后 |
|---|---|---|---|
| 2024 初小盘股灾 | −16.12 | 4.89 | **−3.26**（极罕见） |
| 2026-09 当前 | −13.49 | 12.16 | **−1.12**（常规） |

原始值看似相当，**风险调整后信号强度差约 3 倍**——低波动期的小差价反而是更强的信号。

### 10.2 口径定稿

`adj = 差值 ÷ 该差值近 250 日滚动标准差`（`min_periods=60`，与 `pct` 窗口一致）

**被否掉的两个候选方案**（记录以免日后重走弯路）：

| 方案 | 定义 | 否决原因 |
|---|---|---|
| A | `(diff − rolling_mean(diff)) / std(diff)` | 减均值引入「近一年是牛是熊」的依赖，退化成 250 日排位，与 `pct` 分位重复 |
| B | `tech/σ_tech − div/σ_div` | 中性点不是 0：两腿同涨 10% 时科技因波动大反算出负值，变成「谁夏普高」而非「资金偏好」 |

**定稿方案**（`diff / σ_diff`，不减均值）通过两项检验：中性性（两腿同收益 → 0.00）、
分布（全史 `mean 0.084 / sd 1.095`，理想归一化应接近 0 与 1；剪刀差同法处理后 `mean −0.012 / sd 1.097`）。

### 10.3 落地清单

| 层 | 内容 |
|---|---|
| 数据层 | `market_style_daily` 加 **2 列**：`risk_appetite_adj20` / `scissors_adj20`（由 `_ensure_columns` 自动 ALTER 补齐） |
| 采集器 | `market_style_sync._risk_adj()`；常量 `STYLE_ADJ_COLS` / `STYLE_ADJ_DDL` / `STYLE_ADJ_LOOKBACK=250` / `STYLE_ADJ_MIN_PERIODS=60`。新列由指数列全量重建自然带出，**无需 `full_refresh`**（该开关只管宽度列增量门控） |

### 10.4 与分位的分工（用户可感知的差异）

| 指标 | 回答的问题 | 特性 |
|---|---|---|
| `pct`（近 250 日分位） | 在近一年**排第几** | 纯相对排位；0~100 均匀分布；受「近一年恰好是牛是熊」影响 |
| `adj`（风险调整） | 偏离自身**风险尺度**几个单位 | 含幅度信息；不依赖区间选择；可跨期比较 |

当前实测：`−11.98pp` 对应 `pct 7.6%`（近一年极端防守）↔ `adj −0.99σ`（偏离约一个标准差）。
**两者并列展示、互为参照**——「极端」的印象来自近一年科技偏强形成的高基线，而按自身风险尺度衡量只是约一个标准差。

## 12. P1 落地记录：零采集成本阶段（2026-09-15）

### 12.1 判定方法：方向背离法（不做加权打分）

§1.0 说了「背离是最高级用法」，但没说怎么判。P1 定的方法刻意**可解释、可复核**：

| 步骤 | 规则 |
|---|---|
| ① 取变化 | 每个维度取**自身 20 日变化**（不是水平值——水平值高低不可比） |
| ② 定死区 | 死区 = **该维度自身近一年 20 日变化幅度的中位数 × 0.5**（`DEAD_RATIO`），低于死区视为「噪声不动」 |
| ③ 判方向 | 两维方向**相反且都超出各自死区** → `diverge`；同向 → `agree`；任一在死区内 → `neutral`；无料 → `nodata` |

> **为什么不用打分**：打分说不清分数怎么来的，方向背离可解释、可复核，且天然适配「维度数量会继续增加」；
> 每个维度**用自己的尺度做死区**，避免了「国债收益率变化 1bp」与「两融变化 2.63 万亿」直接比较的荒谬。
> 常量：`WINDOW=250`、`CHG_LAG=20`、`DEAD_RATIO=0.5`；实现见 `backend/app/analysis/cross_check.py`。

### 12.2 六维交叉印证（`cross_check.py`）

### 12.3 新模块「板块轮动」（`sector_rotation.py` + `/analysis/sector-rotation`）

## 13. 盘后排期契约订正（2026-09-16）

> 缘起：P1 交付次日例行巡检时，发现「市场风向」的交叉印证退化成 `nodata`，

### 13.1 缺陷一：调度器「进程存活但调度线程卡死」

| 观感 | 实际 |
|---|---|
| `/api/health` 正常返回 | 进程确实活着 |
| `scheduler_running=true`、`scheduled_count=26` | **接口认为一切正常** |
| —— | **11.5 小时零任务派发**（07:31 停摆；`news_fetch` 是 30 分钟班次，应有 ~23 条记录，实际 0 条） |

**唯一可靠判据**：`GET /api/jobs/tasks` 的 **`next_run`** 全部停在**过去**。
⚠️ 字段名是 `next_run`，**不是** `next_run_time` —— 差几个字，探针会误判「调度器已死」。

**诱因**：疑似执行器线程池被极端耗时任务耗尽。近 7 天多次出现同类任务：
`financial_abstract_sync` 实测跑 **11 小时 51 分**，`sw_industry_sync` 最长 **21.9 小时**。

**处置**：重启即可自愈 —— `reap_orphan_runs()` 清僵尸 + `catchup_missed()` 自动补跑遗漏班次。

### 13.2 缺陷二：快照 × 日线排期竞态是**结构性**的，不是偶发

`stock_daily_incr` 实测常态耗时 **15~50 分钟**（9/11=1505s、9/14=2560s、9/15=938s），
而原排期是 `market_style_sync` 18:45、`market_current_sync` 19:30 —— **正常交易日里两者必然早于日线完成**。

**实证**：9/16 日线 19:04 开跑，物化表 19:04:54–19:07:35 就 success 了 → `market_style_daily[9/16]`
宽度类字段全 NULL → 交叉印证 `micro` / `pxvol` 当场退化为「数据缺失」。

**连锁伤害（新查出）**：

```
9/15 19:30 快照在日线未完成时触发 → 只写 2820 行（当日最终 5119 行）
        ↓
9/15 19:52 起 stock_info_sync 连续失败 6 次，错误恒为「本地快照仅 2820 只，不可作全市场名单」
        ↓
A 股在册名单停更 6 个班次
```

`stock_info_sync` 自身护栏是对的（拒绝用残数据污染名单），**错的是上游喂了残数据** ——
但下游把「上游残缺」报成了「自身失败」，把真实根因掩盖了。

### 13.3 处置

**① 排期后移**（`PUT /api/jobs/tasks/{name}` 会热同步调度器，**改完即时生效、无需重启**）：

| 任务 | 原 | 新 | 依据 |
|---|---|---|---|
| `market_style_sync` | 18:45 | **20:05** | 输入为个股日线，18:45 必然早于日线完成 |
| `market_current_sync` | 19:30 | **20:15** | 同上；且残快照会毒害下游名单任务 |
| `index_market_sync` | 18:30 | **不动** | 只输出指数行情，不依赖个股日线 |

新链条：`19:00 日线 → 20:05 物化表 → 20:15 快照 → 20:30 体检`。
已回写 `seed_task_config.py`，并同步 `seed_market_style.py`（后者一度仍是 18:45，重跑会把排期改回去 —— 已对齐并标注权威来源）。

## 15. 卡片墙表述与结构优化（2026-09-25，v1.2）

### 15.1 起因与结论

用户评：「**卡片看不出重点、判读条像在念 KPI 的数字**」。诊断后拆成两个正交问题：

| | 问题 | 结论 |
|---|---|---|
| **Q1** | 卡片墙的**表述层**与**结构层** | 表述层建立**四判据 V1~V4**（§15.2）；结构层**按 `detail` 分 5 组** + 宽度三档（§15.3） |
| **Q2** | 详情页的**大卡要不要拆** | **不拆**（§15.4）。大卡信息密度高，拆开会让「同一块图表被切成两屏」；改做标题去噪 + 邻接重排 + 卡内分区小标题 |

三项待拍板项均按 AI 建议采纳：`concept_median` 上卡、接受宽度分档、详情页本轮一起改。

### 15.2 表述层：判读条四判据 V1~V4（registry 契约 ⑨）

> **一句话总纲：判读条给「判断与影响」，KPI 给「读数与分位」。**
> 判读条一旦复述 KPI 的数字或状态词，就是冗余 —— 用户等于看两遍同一个信息。

| 判据 | 定义 | 阈值 | 为什么 |
|---|---|---|---|
| **V1 无重复词** | `headline` 内部不得出现出现 ≥2 次的 ≥2 字子串 | 违规数 = 0 | 「大小盘**小盘**占优」「与美股基本持平，与港股基本持平」——机器拼句子时极易撞车 |
| **V2 不复述数字** | `headline` 里的数值，在**同卡 KPI**（label/value/status/scale）里再次出现的比例 | **< 50%** | 判读条写「近一年 19.1% 分位」就是把 KPI 念一遍 |
| **V3 长度** | `headline` 字数 | **≤ 28 字** | 超过会在半宽卡上折 3~4 行，把 KPI 区推下首屏 |
| **V4 不回声 status** | `headline` 不得完整包含**同卡任一 KPI `status`** 的 ≥4 字片段 | 违规数 = 0 | 判读条退化成状态词回声（实测踩过：「情绪转冷」「落后美股」被逐字抄进判读条） |

**V4 是最后发现的、也最容易踩的**：写判读条时若直接调用生成 `status` 的那个函数，就会自动违规 ——
因为 `status` 的返回值**正是**同卡 KPI 的 status（实测 `sentiment ⊃「情绪转冷」`、`gap_cn_us ⊃「落后美股」`）。
**修法是换一层语义**：`_pos_sent_note` 输出**趋势语**（「情绪正在修复 / 仍在探底」），
而 `_sent_status` 输出**状态语**（「情绪偏暖 / 情绪转冷」）—— 同源不同表述，既不重复又互相印证。

**验收（`_scratch/_probe_cardtext.py`，重启后端后实测）**：

```
V1 含重复词        : 0/15 ✅（期望 0）
V2 数字复述率 ≥50% : 0/15 ✅（期望 0）
V3 判读条 >28 字   : 0/15 ✅（期望 0）
V4 状态回声        : 0/15 ✅（期望 0）
最长判读条 19 字 / 平均 13.3 字
组数/每组卡数      : 5 组 → 市场风向(3) | 板块轮动(3) | 钱贵不贵(3) | 跨市场对照(3) | 资金温度(3)
上墙论据数分布     : {1: 8, 2: 5, 3: 2}     总 KPI 28 / 上墙 24
```

改前基线的**具体条目**（据本轮施工记录，非估算总数）：
`_verdict_position` 原为 `近一年低位（19.13% 分位）、情绪转冷`（踩 V1+V2+V4 三项）；
`_verdict_structure` 会拼出「大小盘**小盘**占优」（V1）；
`_verdict_relative` 会拼出「与美股基本持平，与港股基本持平」（V1）；
`_verdict_valuation` / `_verdict_level` / `_verdict_policy` 均直接念分位/报价（V2）。

### 15.3 结构层：分组 + 宽度三档 + 卡片头

**① 分组（零新增字段）**：`detail` 字段本就指向详情页 ⇒ 15 张 track 卡天然聚成 5 组 × 3 卡。
组标题取该 `detail` 模块的 `name`。**领域名全页只出现 5 次**（原来是每张卡名里一个，共 15 次）。

**② 卡片头改造**（三处）：

| 位置 | 改前 | 改后 | 理由 |
|---|---|---|---|
| 卡片名 | `市场风向 · 位置`（含领域前缀） | `位置` | 领域名让组标题承担，卡片名不重复 |
| 卡片名下方 | 无 | 问句副标题「现在处在什么位置」 | 短名脱离上下文后读不懂，问句是锚 |
| 右上角 | 「跟踪」标签（15 次重复） | `截至 09-24`（`as_of`） | 按规范 §2.1 该位放**数据新鲜度**；取不到就不显示，前端不编造「最新」 |

**③ 宽度三档**：`card_span` = `narrow`(1) / `half`(2~3) / `full`(≥4)。
容器列数 = 组内各卡 span 之和（`--ao-cols`），**保证每行铺满、右侧不留空档**。
`minmax(0, 1fr)` 而非 `1fr` —— `1fr` 的最小尺寸是 `auto`，长内容会撑破列（本项目已踩过溢出坑）。
断点：1200px 降 2 列、760px 降 1 列（整组降级，卡片 span 一律压到 1 列）。

### 15.4 详情页 Q2：**不拆大卡**，改「标题去噪 + 邻接重排 + 卡内小标题」

用户拍板**不拆**。原因：大卡信息密度高是**优点**（一屏看全对比关系），
拆开会把同一块对比切成两屏，反而增加滚动。改做三件事：

1. **标题去噪**：7 张卡标题去掉「功能清单 / 计数 / 操作提示 / 长解释」——
   例：`市场宽度与量能（4 项清单）` → `上涨是否普遍？量能配不配合？`；
   `指数明细（56 只 · 分组）` → `指数明细`（计数下沉为卡片 caption「共 56 只 · 当前 12 只」）。
   标题改**问句**，让标题回答「这张卡在答什么」。
2. **邻接重排**：「六组等权收益」与「六组风格热力矩阵」归位相邻（原被其它卡隔断，读图要来回跳）。
3. **卡内分区小标题**：多主题的卡内部用小标题切开（宽度 / 量能 / 趋势），
   统一走全局 `.card-sub` / `.card-cap` 两个类，不再每视图各写一套。

### 15.5 顺带修掉的三类漏点

## 15.8 三项实测口径债的处置（2026-09-25，v1.3）

起因：用户指令「这三个问题（`concept_median` 上卡片 / 宽度分档 / 详情页本轮一起改），以及你最后实测发现的
口径债，都统一按照你的建议进行优化吧」。三项债务全部处置完毕——**其中一项结论是「不修」，并给出证明**。

### 15.8.1 债 1：`group` 两套 taxonomy → 收敛为「所属领域」

**症状（用户可见）**：跨市场对照的详情页头部顶着「市场风向」标签。

**根因（实测，非推测）**：

| 事实 | 证据 |
|---|---|
| `group` 是**旧目录 taxonomy**，与卡片墙分组不同源 | `group` 只有 3 个取值：市场风向 8 / 板块与概念 4 / 资金与情绪 8 |
| 卡片墙分组走的是 `detail` 字段（存路由，如 `/analysis/market-wind`）⇒ 5 组 | 组标题取 detail 模块的 `name`，5 组 × 3 卡 |
| 5 个 detail 里 **1 个被错标** | `cross-market` 标 `group=市场风向`，而它本身就是「跨市场对照」这个领域 |
| `group` 有 **2 个真实消费点** | 研究目录分区（`researchByGroup`）+ 详情页头部 `NTag` |

**处置**：`group` 语义收敛为**「该模块所属领域」**，取值 = 卡片墙组标题 = detail 模块的 `name`
（track 卡填其 `detail` 指向的领域名；detail 模块自身即领域，填自身 `name`）。共改 **16 处**
（sector-rotation / money-cost / cross-market / funding-temperature 各 3 张卡 + 1 个 detail 模块；
market-wind 的 4 条本来就是「市场风向」，值不变）。
前端两处随之收敛：`GROUP_ORDER` 由**硬编码的旧五类**改为**从 registry 派生**（将来新增领域自动出现，
不再需要回来改这一行）；详情页 `NTag` 改为**仅在 `group !== name` 时渲染**（track 卡页显示所属领域，
detail 页不与标题重复）。

**验收证据（实测）**：

- `group` 取值分布：`{市场风向:4, 板块轮动:4, 钱贵不贵:4, 跨市场对照:4, 资金温度:4}` —— 每领域 3 track + 1 detail
- 断言①`15/15` track 卡的 `group == detailMeta[detail].name`；断言②`5/5` detail 的 `group == name`
- 浏览器实测页头标签：5 个 detail 页 → `[研究]`（领域标签不再与标题重复）；
  `/analysis/market-wind-position` → `[市场风向, 跟踪]`

### 15.8.2 债 2：宽度跨组偏差 → **判定为非缺陷，不修**（附证明）

**实测事实**（`_probe_debt.py`；占比与行宽无关，故用占比表述）：

| 组 | Σspan | span 构成 | 组内占比 |
|---|---|---|---|
| 市场风向 | 11 | half, narrow, half | 36.4 / 27.3 / 36.4 % |
| 板块轮动 | 12 | half, half, half | 33.3 ×3 |
| 钱贵不贵 | 9 | narrow ×3 | 33.3 ×3 |
| 跨市场对照 | 11 | half, half, narrow | 36.4 / 36.4 / 27.3 % |
| 资金温度 | 9 | narrow ×3 | 33.3 ×3 |

同档跨组偏差：**narrow 22.2%**（27.3% ↔ 33.3%）、**half 9.1%**（33.3% ↔ 36.4%）。

> ⚠️ **勘误（推翻本文档 v1.2 §15.7 的结论）**：v1.2 写「跨组差异在分组标题隔断下几乎不可察」。
> 该结论**只对 `half` 成立（9.1%）**，对 `narrow` **不成立（22.2%）** —— 当时是按单个样本目测下的结论，
> 没有逐组算占比。此处更正，不回头改写 §15.7。

**精确结论**：偏差在三约束下**唯一确定**，不存在「既保留档位语义、又抹平偏差」的方案：

1. 每行铺满 100% ⇒ 组内占比 = `span / Σspan`
2. 每组恰好 3 张卡 ⇒ Σspan 只能取 9 / 11 / 12
3. 档位由上墙论据数唯一决定（1 个→narrow / 2~3 个→half）⇒ 「哪张卡是什么档」也被钉死

**反事实（算过，但不可实施）**：若允许打破约束 3，最优组构成是 `3×nnh + 2×nhh`，偏差可降到 **10.0%**。
但**档位不是样式，而是内容上限**（`CARD_KPI_LIMIT`：narrow 1 / half 3 / full 6）——
重排档位等于改变「每张卡显示几个论据」，即**用内容换像素**，不划算，不实施。

**处置**：不改布局；量化与断言固化在 `_probe_debt.py` 作为长期守卫。
若将来口径改为「跨组同档等宽」，切换方案已备：把 `--ao-cols` 固定为 `12`、span 保持 3/4
⇒ 同档占行恒定 `narrow 25% / half 33.3%`；代价是 Σ<12 的组行末留白（`n,n,n` 组 25%、mixed 组 8.3%）。

### 15.8.3 债 3：KPI 标签截断 → 折行修掉（不改口径文案）
