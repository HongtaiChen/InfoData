# InvestBuddy 分析研究模块 交互设计规范 v0.2（定稿）

> 版本：2026-09-13 · 状态：**v0.2 定稿**（三个决策点已确认：总览=卡片墙 / 旧分析=下线保留码 / 注册=配置文件先行）
> 前置：旧「分析研究」页（股息率排行/概念排名/YTD 三个 Tab）定位粗糙，**先下线不考虑**；
> 本规范面向"分析研究内容会持续增加"的现实，**框架先行**——先定扩展机制，再逐个填充模块。

---

## 0. 一句话定位

> **分析研究 = 一个可持续插入分析模块的工作台**。
> 框架解决三件事：模块怎么组织（导航）、模块长什么样（统一布局）、模块怎么接入（注册机制）。

---

## 1. 设计原则（5 条）

1. **注册即扩展**：新增一个分析 = 后端加一个模块 + 注册一条元数据；前端框架零改动（内置视图组件拼装）。
2. **跟踪与研究分流**：跟踪型（每日自动更新、看状态变化）与研究型（按需查参数、下钻明细）交互不同，不硬塞一个模板。
3. **结论先行**：每个模块首屏必须先给"结论数字/信号"，图表和明细都是论据——分析页不是数据页。
4. **口径透明**：每个指标旁边可查计算口径（tooltip/口径卡），与设计规范的指标定义一一对应，杜绝"数字怎么来的"黑箱。
5. **下钻闭环**：分析模块之间、分析→行情/概念/个股之间可跳转，延续"指数→行业→概念→个股"的下钻链。

---

## 2. 信息架构（两层）

```
分析研究（/analysis）
├── 总览页 /analysis            —— 跟踪型模块的卡片墙 + 研究型模块的入口目录
└── 详情页 /analysis/:moduleId  —— 单个分析模块的完整视图（AnalysisShell 容器）
```

### 2.1 总览页（默认落地页）

- **跟踪卡片区**：每个跟踪型模块一张摘要卡（名称 + 关键信号数字 + 一句状态 + 更新时间），
  例如「市场风向」卡显示：风偏分数 +6.5 / 剪刀差 +3.2pp / 状态标签「风偏升温」。
  每天 10 秒扫一眼，点卡片进详情。
- **目录区**：研究型模块按分组列出（名称 + 一句话说明），点击进详情。
- 分组固定五类（后续新增模块必须归入其一）：
  ① 市场风向 ② 板块与概念 ③ 个股基本面 ④ 资金与情绪 ⑤ 跟踪清单

### 2.2 详情页（AnalysisShell 统一容器）

所有模块共用同一骨架，**从上到下固定五段**：

| 段 | 内容 | 说明 |
|---|---|---|
| ① 标题区 | 模块名 + 口径说明（? tooltip）+ 数据截至时间 + 所处分组面包屑 | 截至时间来自物化表 MAX(trade_date)，滞后会变琥珀色 |
| ② 参数区 | 周期/日期等参数 chips（NSelect/DatePicker），改变即刷新 | 参数 schema 由模块元数据声明 |
| ③ 结论区 | 2~4 个 KPI 结论卡（大数字 + 状态词），**金色仅用于系统产出的亮点信号** | 红涨绿跌仅出现在行情数字 |
| ④ 主视图 | 模块主图表（从内置视图组件中选 1~2 个拼装） | 见 §4 视图组件清单 |
| ⑤ 明细区 | 可展开的数据表 + 下钻按钮（跳行情/概念/个股） | 表格列由模块声明 |

## 3. 扩展机制（框架核心）

### 3.1 后端：模块注册表（registry）

- 新表 `analysis_registry`（或先配置文件）声明每个模块的元数据：

```json
{
  "module_id": "market-wind",
  "name": "市场风向",
  "group": "市场风向",
  "kind": "track",              // track=跟踪型 / research=研究型
  "desc": "六组指数风向 + 大小盘剪刀差 + 风偏分数",
  "api": "/api/analysis/market-wind",
  "params_schema": [ {"key":"window","type":"select","options":[5,20,60],"default":20} ],
  "views": ["group-heat-bar", "size-gradient", "wind-gauge", "dual-line"],
  "drilldown": [ {"label":"看K线","target":"market"} ]
}
```

- API 约定：`GET /api/analysis/registry`（总览页目录用）+ `GET /api/analysis/<module_id>`（模块数据，统一返回 `{as_of, kpis[], main_view, detail_table}` 骨架）。
- **新增模块的标准动作**：`app/analysis/` 加计算模块 → registry 注册 → 完毕。后端到前端一条链，无散落改动。

### 3.2 前端：组件注册表 + 内置视图库

- 路由 `/analysis/:moduleId` 动态匹配；`viewsById` 映射表把 module_id 指到对应视图组件（缺失则显示"模块开发中"占位）。
- **内置视图组件**（先建 6 个，覆盖绝大多数分析形态，新模块优先复用）：

| 组件 | 形态 | 适用 |
|---|---|---|
| `KpiCards` | 2~4 张结论大数字卡 | 所有模块的结论区 |
| `GroupHeatBars` | 分组水平热力条（红涨绿跌） | 六组收益、行业对比 |
| `SizeGradient` | 有序梯度条（超大盘→微盘） | 市值风格、规模对比 |
| `DualLineTrend` | 双轴/双线时序 + 拐点标注 | 剪刀差、风偏分数等轮动序列 |
| `RankTable` | 排行表（可切区间/正序倒序） | 股息率、概念、YTD 等排行型 |
| `DrillLink` | 下钻按钮组（K线/概念/个股跳转） | 明细区统一交互 |

## 4. 首发模块：市场风向（P0）

### 4.1 数据层：物化表 `market_style_daily`（每日一行）

挂在 `index_market_sync`（18:30）之后 18:45 跑，纯库内 SQL 计算、幂等重建当日行：

| 字段组 | 字段 | 口径 |
|---|---|---|
| 六组收益 | `ret_bench_20/60, ret_size_20/60, ret_tech_20/60, ret_sent_20/60, ret_div_20/60, ret_pol_20/60` | 组内等权 N 日收益(%) |
| 剪刀差 | `scissors_20, scissors_60` | (中证1000+中证2000 等权) − (上证50+沪深300 等权) N 日收益 |
| 风偏 | `risk_appetite_20` | 科技成长组 − 股息防守组（20 日） |
| 情绪 | `sentiment_20` | 证券公司 − 中证全指（20 日超额） |
| 政策 | `policy_excess_20` | 中证全指房地产 − 中证全指（20 日超额） |
| 大势 | `bench_pos_pct` | 中证全指在近 250 日高低区间的分位(%) |

> 好处：口径版本化可回测、前端 O(1)、可加 DQ 规则（freshness + 行数）、未来直接喂 AI 生成日报。

### 4.2 视图层（AnalysisShell 拼装）

- ③ 结论区 KPI：`风偏分数`（正=进攻/负=防守，金色高亮极值）+ `大小盘剪刀差` + `大势位置`（分位%）
- ④ 主视图：`GroupHeatBars`（六组 20 日收益热力条）+ `DualLineTrend`（剪刀差 & 风偏分数双线，近 1 年）
- ⑤ 明细区：六组内 21 只指数列表（最新涨跌/20 日收益），行内下钻 K 线
- 附：状态词规则（首版简单化）——风偏分数 >0 且近 5 日走扩 =「风偏升温」；<0 且收敛 =「防守松动」；其余 =「均衡震荡」
