# 投资环境 · 指标自由组装分析 方案（补充设计）

> 日期：2026-10-18 ｜ 状态：**草案（待评审）**
> 关联：`投资环境模块_设计方案_v0.2_2026-10-18.md`
> 回答的问题：**指标落地后都是 SQL，如何让我更自由地组合、对比、沉淀分析？**

---

## 0. 定位：组装是"旁路"，不是"替代"（重要）

**「一溜下来直接看」的固定内容块流，永远是投资环境页的默认主体视图，不可被取代。**

- 打开 `/environment`，看到的**就是** v0.2 定义的那一溜固定内容块（当日涨跌幅 → 多窗口矩阵 → 均线 → 量价 → 技术指标 → 支撑阻力 → 回撤 → 波动率 → Beta → 相关性 → 估值分位 → 盈利成长 → 宏观），开箱即看，无需任何操作。
- **自由组装**只是页面上的一个**旁路入口**（如右上角「自定义分析」按钮）：你想跨指标对比、或拼一个自己的看板时，才切进去；不想用，完全不打扰默认流。
- 二者共享同一套底层：固定内容块 = 官方预置的命名查询的"固定视图"；自由组装 = 把同样的命名查询**重新排列组合**。**同一套数据、同一套积木，两种用法**，不重复建设。

```
默认（一溜下来看） ──────────►  固定内容块流（v0.2 主体）
        │
        └── 右上角「自定义分析」──► 自由组装器（本方案）
              组合出的视图可"另存"，与固定内容块平级共存、互不干扰
```

---

## 1. 结论先行：指标 = 命名查询（Named Query），组装 = 拖查询 + 拼维度

你的判断完全正确：技术面/基本面指标的本质就是**一条条 SQL**（有的简单、有的含窗口函数/跨表 JOIN）。"自由组装"不应该意味着"每次手写 SQL"，而应该是：

1. **把每个指标固化成一条"命名查询"（Named Query）** —— 已写好的、带参数、带口径说明的 SQL，作为可复用的积木；
2. **组装时只做三件事**：选哪几条查询、对齐到哪个共同维度（时间/指数）、用什么图展示；
3. **结果一键出图 + 可保存成"视图"，可复用、可分享、可沉淀**。

这样你既有"自由写 SQL"的底层（已有 `SqlExploreModal`），又有"像搭积木一样组合"的高层，不用每次重写 JOIN。

---

## 2. 分层：三层能力，各司其职

```
第 3 层 · 视图/看板层  —— 把若干命名查询拼成一个"自定义分析视图"，存下来复用
第 2 层 · 组装层      —— 拖/选命名查询，指定对齐维度(时间/指数)，选图表
第 1 层 · 查询层      —— 单条命名查询(指标SQL)；底层可下钻到原始 SQL 自由编辑
```

### 第 1 层：命名查询（指标积木）

每个投资环境指标，除了物化表（`env_index_tech_daily` 等）外，同时登记一条**命名查询**，包含：

| 字段 | 说明 | 示例 |
|---|---|---|
| `query_name` | 唯一名 | `index_pe_ttm_series` |
| `label` | 中文显示名 | 沪深300 PE-TTM |
| `sql` | 参数化 SQL（`:param` 占位） | `SELECT trade_date, pe_ttm FROM index_valuation_daily WHERE index_code=:code ORDER BY trade_date` |
| `params` | 参数清单（类型/默认值/可选值） | `code`（指数，下拉） |
| `x_axis` / `y_axis` | 默认横/纵轴字段 | `trade_date` / `pe_ttm` |
| `chart_hint` | 默认图表类型 | `line`（曲线）/ `heatmap`（矩阵）/ `bar` |
| `口径` | 口径说明（复用 TermTip） | "TTM 口径，来源 index_valuation_daily" |
| `粒度` | 数据粒度（日/月/季） | 日频 |

**来源**：v0.2 里的每个内容块，其背后的查询都登记成一条命名查询。内容块 = 命名查询的"固定视图"，命名查询 = 内容块的"可复用积木"。

**自由编辑**：命名查询的 SQL 可展开编辑（复用 `SqlExploreModal` 的安全校验：只读 SELECT/WITH + 黑名单 + LIMIT 保护），改完即作为自定义变体。

### 第 2 层：组装（对齐维度 + 选图）

组装器的核心是解决"**不同指标怎么放在一起比**"——这是自由组合真正的难点：

| 场景 | 对齐方式 | 示例 |
|---|---|---|
| 同一指数，不同指标 | 按 `trade_date` 对齐（inner join 时间轴） | 沪深300 的 PE 曲线 + 价格曲线叠放（双 Y 轴） |
| 不同指数，同一指标 | 按 `trade_date` 对齐，指数作为序列 | 上证/沪深300/创业板 的涨跌幅并排 |
| 跨粒度（日 vs 季） | 重采样对齐（日→月末 / 季末取点） | 估值(日) + ROE(季) 对齐到季度末 |
| 完全异构 | 不强制对齐，各自成图，网格排布 | 宏观(月) + 技术(日) 分块并列 |

**组装操作**：
1. 从指标库勾选 N 条命名查询；
2. 指定"对齐维度"（默认 `trade_date`，可改 `month` / `quarter`）与"序列维度"（哪列当分组，如 `index_code`）；
3. 每列绑定图表（曲线/柱/面积/热力/散点），可多指标共用一个坐标系（双 Y 轴）或各自独立；
4. 预览 → 命名保存为"视图"。

### 第 3 层：视图/看板（沉淀复用）

保存的"自定义分析视图"是一份**声明式配置**（JSON，非硬编码前端），存库可复用：

```json
{
  "view_name": "沪深300 估值+价格 联动",
  "queries": [
    {"query": "index_pe_ttm_series", "params": {"code": "000300"}, "axis": "left"},
    {"query": "index_close_series", "params": {"code": "000300"}, "axis": "right"}
  ],
  "align_by": "trade_date",
  "layout": "overlay"
}
```

- 视图可**重新打开、再编辑、导出 SQL**（把组合翻译成一条合并 SQL，供你在 SqlExplore 里二次加工）；
- 视图与"内容块"的关系：内容块是官方预置的视图，你的自定义视图和官方内容块**平级共存**，都在"投资环境"下可见。

## 3. 落地：最低成本路径（复用现有基建）

你已有 `sql_explorer.py`（安全只读 SQL）+ `SqlExploreModal`（手写 SQL 出表）。自由组装**不是另起炉灶**，而是在这之上加三层薄封装：

### 3.1 新增数据表（1 张配置 + 1 张视图，均为轻量）

| 表 | 内容 |
|---|---|
| `env_named_query` | 命名查询登记表（query_name/label/sql/params/x_axis/y_axis/chart_hint/口径/粒度） |
| `env_analysis_view` | 自定义视图配置表（view_name/queries_json/align_by/layout，存 JSON） |

> 命名查询的 SQL 执行复用现有 `/explore` 的安全通道（白名单 SELECT + 黑名单 + 强制 LIMIT），**不新增可写 SQL 入口**，安全边界不扩大。

### 3.2 新增接口（复用现有 explore 引擎）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/environment/queries` | 列出命名查询（积木清单，含参数 schema 与口径） |
| GET | `/api/environment/queries/{name}` | 取单条命名查询详情（含 SQL 全文，可编辑） |
| POST | `/api/environment/queries/{name}/run` | 带参数执行命名查询（底层调 `_validate` + 执行，返回行列） |
| GET/POST/PUT | `/api/environment/views` | 视图的列表/保存/更新（声明式 JSON） |
| POST | `/api/environment/views/{name}/run` | 执行整个视图：逐条跑查询 + 按 align_by 合并 + 返回多序列结果 |
| GET | `/api/environment/views/{name}/export-sql` | 把视图导出为一条合并 SQL（供 SqlExplore 二次加工） |

### 3.3 前端：组装器界面（复用 `SqlExploreModal` + `ExploreChart`）

- 左侧：指标积木清单（可搜索、按技术面/基本面分组，带口径 TermTip）；
- 中间：画布，拖入的查询各自渲染（复用 `ExploreChart`，支持折线/柱/面积/热力）；
- 顶部：对齐维度选择 + 序列维度选择 + 图表类型切换；
- 底部：预览 → 保存为视图 → 导出 SQL。

---

## 4. 边界与取舍（明确"不做"什么）

- **不做通用 BI**：不支持任意多表自由 JOIN 的可视化拖拽建模（那是 Superset/Metabase 的活），只做"预置积木的组合"。
- **不放开写权限**：组装始终走只读 SELECT 通道，任何 DML/DDL 仍被黑名单拦截；参数全部走占位符绑定，杜绝注入。
- **不自动生成指标 SQL**：命名查询由我们预置 + 你手改，不做"自然语言→SQL"（除非后续引入 LLM，且结果仍过只读校验）。
- **组合结果的正确性由对齐规则保证**：跨粒度、跨口径的组合会显式标注"粒度 X vs 粒度 Y"提示，避免误解（沿用项目"口径透明"的一贯原则）。

## 5. 与 v0.2 的关系与分期

| 期 | 内容 |
|---|---|
| v1 | 先落地 v0.2 的固定内容块（数据 + 图形 + 口径），**同时把每个内容块背后的查询登记成命名查询**（顺手做，成本低） |
| v1.5 | 上线组装器：命名查询积木 + 拖拽对齐 + 出图 + 保存视图 + 导出 SQL |

> 这样 v1 交付时，你既拿到了"官方内容块"，又已经积攒好了"积木库"，v1.5 只差组装器的 UI 层。
