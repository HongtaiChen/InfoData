## 一、问题 1：`index_valuation_daily` 只有 7 个指数的根因

### 结论先行

**不是"其他指数不支持"，而是采集器代码里硬编码只配了 6 个中证指数 + 1 个全A 横截面。** 数据源本身能覆盖的指数远不止 7 个，限制是「人（代码配置）为」的，不是「数据源」的。

### 证据链

**（1）采集器是刻意写死清单的**

`backend/app/collectors/index_valuation_sync.py` 里有三个硬编码字典：

```python
CSINDEX = {            # 中证官网源：6 个指数（滚动 20 交易日窗口）
    "000300": "沪深300", "000016": "上证50", "000905": "中证500",
    "000852": "中证1000", "000688": "科创50", "931775": "中证全指房地产指数",
}
LEGU = {               # 乐咕长历史源：4 个指数（2005 至今月末序列）
    "沪深300": "000300", "上证50": "000016", "中证500": "000905", "中证1000": "000852",
}
ALL_A_CODE = "ALL_A"   # 全A 等权/中位口径（非指数，单独 1 行）
```

`CSINDEX` 6 个（科创50/房地产只有 39 行，因 2026-08 才接入）+ `LEGU` 4 个（与 CSINDEX 重叠）+ 全A 1 个 = **去重后恰好 7 个 index_code**，和库里 `GROUP BY index_code` 的结果（7 个）完全吻合。

**（2）这个采集器当初是"为了算 ERP 股债收益差"建的，不是为"全指数估值"建的**

文件头注释写得很清楚（`index_valuation_sync.py` 第 3-25 行）：

> 库内没有任何指数估值数据……本采集器补上这个分母，ERP（股权风险溢价）随之成立。

也就是说，它的**设计目的**是为「市场风向 · 股债性价比」蓝图 B 提供估值分母，只需要几个核心宽基就够了，**没打算覆盖全量指数**。范围是"够用即可"，不是"数据源不支持"。

**（3）中证官网源其实支持更多指数（实测）**

实测 `akshare.stock_zh_index_value_csindex`（中证指数官网官方接口）：

| 指数代码 | 名称 | 结果 |
|---|---|---|
| 000300 | 沪深300 | ✅ |
| 000016 | 上证50 | ✅ |
| 000905 | 中证500 | ✅ |
| 000852 | 中证1000 | ✅ |
| 000688 | 科创50 | ✅ |
| **000001** | **上证指数** | ✅（未配置，但源支持） |
| **000985** | **中证全指** | ✅（未配置，但源支持） |
| **H30374** | 中国内地全指 | ✅ |
| 931775 | 房地产 | ✅ |
| 399006 | 创业板指 | ❌ HTTP 404 |
| 399005 | 中小板指 | ❌ HTTP 404 |

→ 中证官网源能覆盖**沪市/中证/北证系**指数，唯独**深市系（399 开头，创业板指/深证成指等）404**——因为它们归**国证指数（原深证信息）编制**，不在中证官网。

### 为什么 7 个里只有 5 个有长历史，科创50/房地产只有 39 行？

因为长历史分位依赖 `LEGU`（乐咕）源，而 `LEGU` 只有 4 个宽基。科创50、房地产只靠 `CSINDEX` 中证官网源（滚动 20 交易日），所以**只有 20 天左右历史**——库里 39 行 = 20 交易日 × 约 2 个多月累积，**永远攒不出"历史分位"**。

## 二、问题 1 附带：为什么 `index_valuation_daily` 和 `dc_index_market` 没合并成一张表？

### 结论：**刻意分开，不是遗漏。** 两张表解决的是两个不同问题。

| 维度 | `dc_index_market` | `index_valuation_daily` |
|---|---|---|
| **本质** | 指数**行情**（价格/量） | 指数**估值**（PE/PB/股息率） |
| **字段** | open/high/low/close/volume/amount/涨跌/换手 | pe_lyr/pe_ttm/股息率/分位/close_point |
| **频率口径** | 日频，逐交易日 | 中证官网滚动 20 日 + 乐咕**月末序列**（非逐日） |
| **数据源** | 中证官网行情 API + 国证 + 腾讯 | 中证官网估值 API + 乐咕 + 全A |
| **覆盖** | 21 个指数，全字段，1990 至今 | 7 个指数，估值字段，2005 至今 |
| **粒度** | 一个指数一行一交易日 | 一个指数一行一 (交易日 × source)，**多源并存** |

**三个硬理由不合并：**

1. **频率不对齐**：行情是逐日，估值长历史是"月末 + 最新"（乐咕沪深300 只有 258 个点 vs 行情 5000+ 个交易日）。硬塞一张表会产生海量 NULL 行。
2. **多源口径必须分离**：估值表有 `source` 列（csindex/legu/all_a），刻意"不合并成一条序列"，因为**不同源方法论不同、数值不能直接比大小**（注释里实测：沪深300 滚动 PE 中证官网 16.92 vs 乐咕 12.68）。这是 registry 第一原则"把口径分歧留下来"。
3. **采集节奏不同**：行情每日收盘增量；估值三源（中证滚动 + 乐咕月末 + 全A 横截面）各自独立 upsert，链路、失败重试、DQ 规则都不一样。

> 类比：`stock_market_daily`（个股行情）和 `stock_financial_abstract_ths`（个股财务）也是分两张表——**行情和基本面是两个数据域**，指数同理。

## 三、问题 2：PB 为什么只支持 4 个宽基？

### 结论先行

**PB 只支持 4 个宽基，是"乐咕乐股"这个第三方源只公开了这 4 个指数的 PB 历史**（写死在乐咕自己的接口字典里），**不是"其他指数本来就没有 PB 数据"**。PB 数据本身对所有指数都存在（交易所/指数公司都有），只是**免费公开、能程序化抓取长历史的源很少**。

### 证据链

> ⚠️ **勘误（2026-10-18 第二次调研）**：上一份《数据探测结论》里"PB 只支持 4 个宽基"的结论**有误**。根因是当时只测了 4 个指数名就下了结论。实际上乐咕 `stock_index_pe_lg` / `stock_index_pb_lg` 源码的 `symbol_map` 里**写了 12 个指数**，包含深市的**创业板50、深证100、深证红利**等。本报告以本次源码级核实为准。

**（1）PB 源是乐咕 `stock_index_pb_lg`，实测支持 12 个指数（非 4 个）**

读 `akshare.stock_feature.stock_a_pe_and_pb` 源码，`stock_index_pe_lg` 和 `stock_index_pb_lg` 的 `symbol_map` **完全一致**，均为 12 个：

```
上证50(000016) / 沪深300(000300) / 上证380(000009) / 创业板50(399673.SZ) /
中证500(000905) / 上证180(000010) / 深证红利(399324.SZ) / 深证100(399330.SZ) /
中证1000(000852) / 上证红利(000015) / 中证100(000903) / 中证800(000906)
```

实测（PE）：上证50/沪深300/上证380/**创业板50**/中证500/上证180 均 OK（2005~2026 全史），其余 6 个当时返回 429/504 是**乐咕服务器限流**（非不支持——`中证1000` 在项目库里本就有 285 行历史数据）。

**关键点**：乐咕**能覆盖深市指数**（创业板50、深证100、深证红利），只是 akshare 的 symbol_map **没有"创业板指(399006)"和"科创50(000688)"**这两个名字。之前测"创业板指/科创50"失败，是**名称不在字典里**，不是乐咕没数据。

**（2）中证官网源有 PB 吗？—— 没有**

实测 `stock_zh_index_value_csindex` 完整字段只有 10 列：日期/指数代码/名称…/**市盈率1/市盈率2/股息率1/股息率2**。**没有 PB 字段**。这就是库里 `index_valuation_daily` 缺 PB 列的直接原因。

**（3）创业板指(399006) / 科创50(000688) 的估值，免费源到底能不能拿？**

| 数据源 | 创业板50(399673) | 创业板指(399006) | 科创50(000688) | 长历史 | 免费可程序化 |
|---|---|---|---|---|---|
| 乐咕乐股 (lg) | ✅ 12 指数之一 | ❌ 不在 symbol_map | ❌ 不在 symbol_map | 2005至今 | ✅（但需 token+限流） |
| 中证指数官网 | ❌ 深市不在 | ❌ 深市不在 | ✅ 当日 PE（无PB、仅20日） | 仅近20日 | ✅ |
| 国证指数官网 cnindex | ✅（官方） | ✅（官方） | — | 仅当日截面 | ❌ 估值需付费协议，公开接口只有行情(OHLCV) |
| 理杏仁 lixinger | ✅ | ✅ | ✅ | 10年+ | ❌ 需 Token（付费） |
| 蛋卷/韭圈儿/雪球 | ✅ 有展示 | ✅ 有展示 | ✅ 有展示 | 有 | ❌ 无公开 API |
| 东财 Choice / Wind | ✅ | ✅ | ✅ | 全 | ❌ 付费终端 |

**结论**：
- **创业板指(399006) 和 科创50(000688) 的 PE/PB 长历史，免费公开、可稳定程序化抓取的源，确实不存在。** 它们的估值要么在国证官网（付费协议/加密 SDK），要么在理杏仁（付费 Token）。
- **但创业板50(399673)、深证100(399330)、深证红利(399324) 等深市指数，乐咕免费就能拿到长历史 PE/PB**——这是之前漏掉的、可立即补上的部分。

### 关键事实：**创业板指、科创50 的估值归属"国证指数"体系**

- **创业板指（399006）**、深证成指、深证100 → **国证指数（深证信息，深交所全资）** 编制，估值数据在国证官网，**不在中证官网**（所以中证官网 404）。
- **科创50（000688）** → 上交所/中证编制，中证官网**有当日 PE**（无 PB、无长历史）。
- **创业板50（399673）** → 深市指数，但乐咕**额外收录**了它（及其余 11 个），所以免费可得长历史。

## 四、对「投资环境」方案的落地影响（更新版）

结合两次调研，估值数据现状精确表述为：

| 指数 | 行情(OHLCV) | PE 长历史 | PB 长历史 | 来源 |
|---|---|---|---|---|
| 沪深300 / 上证50 / 中证500 / 中证1000 | ✅ | ✅ | ✅ | 乐咕 |
| 上证380 / 上证180 / 中证100 / 中证800 / 上证红利 | ✅ | ✅ | ✅ | 乐咕（新增） |
| **创业板50 / 深证100 / 深证红利** | ✅ | ✅ | ✅ | 乐咕（深市，新增） |
| 上证指数 / 中证全指 | ✅ | ⚠️ 仅中证官网当日 PE | ❌ | 中证官网 |
| 科创50 | ✅ | ⚠️ 仅中证官网当日 PE（近20日） | ❌ | 中证官网 |
| 创业板指 / 深证成指 | ✅ | ❌ 免费源无 | ❌ | 国证（付费） |
| 其他（银行/白酒/转债/芯片/房地产等） | ✅ | ❌ | ❌ | — |

### 结论：能免费拿到的估值长历史，一共 12 个指数（乐咕全量）

这 12 个指数里，**6 个已在项目 `index_profile`（21 指数）内**：沪深300、上证50、中证500、中证1000、上证180(?)、中证100(?)。其余（创业板50、深证100、深证红利、上证380、上证红利、中证800、中证100）部分不在当前 21 指数清单，但**都属于可低成本纳入的宽基**。

### 可落地的三条路径（按性价比排序，更新）

**路径 A（推荐，本期就用，零新源成本）——覆盖 12 个乐咕指数**
把乐咕 `symbol_map` 的 **12 个指数全量接入**（PE+PB+长历史分位，一网打尽），而不是只做 4 个宽基。这样：
- 沪深300/上证50/中证500/中证1000 等核心宽基 → 完整估值 ✅
- 创业板50/深证100/深证红利 → 深市代表也有估值 ✅（之前误判为"拿不到"）
- 只有**创业板指(399006)、科创50(000688)** 这两个名字确实拿不到免费长历史

**路径 B（补当日 PE，覆盖中证官网的更多指数）**
中证官网源（`stock_zh_index_value_csindex`）能补**上证指数、中证全指、科创50** 等的当日 PE/股息率（近 20 日），虽无 PB、无长历史分位，但能让这些指数至少显示"当前估值"。

**路径 C（引入付费源，v2 再评估，唯一能补全创业板指/科创50）**
- 理杏仁开放 API：Token 付费，可拿创业板指(399006)/科创50(000688)/全市场的 PE/PB/分位长历史——**这是唯一能把"创业板指、科创50"这两个缺的估值补上的正规路径**。
- 国证官网数据服务：签协议付费，深市指数官方估值。
- 成本/合规需单独立项，不适合本期。

### 建议（回答"想把能做的都做了"）

**本期（v1）落地 = 路径 A + 路径 B 全做**：
1. 乐咕 12 指数全量接入（PE+PB+长历史分位）—— 一次改 `index_valuation_sync.py` 的 `LEGU` 字典从 4 → 12 即可，几乎零成本，却把估值覆盖从 4 个宽基扩到 12 个（含深市）。
2. 中证官网源补当日 PE/股息率（覆盖上证指数/中证全指/科创50 等）。
3. **创业板指、科创50** 这两个确实无免费长历史源，本期显示"当日 PE（科创50 可用）+ 缺长历史分位"占位，等 v2 评估是否引入理杏仁付费源。

### 本期开发落地清单（据此启动）

1. **扩 `LEGU` 字典 4 → 12**（`index_valuation_sync.py`），PE + PB 两个采集器同步扩。
2. **新增 PB 采集**：`stock_index_pb_lg` 目前未接入，补进估值采集器（新增 `pb` 字段到 `index_valuation_daily`，或新建列）。

4. **分位物化**：`pe_ttm_pct10y` 只有 all_a 有值，4/12 宽基分位需在物化层用乐咕月末序列现算。
5. **乐咕限流处理**：实测乐咕接口有 429/504 限流，采集器需加**重试 + 延时 + 单次单指数**策略（不能 12 个并发打）。
