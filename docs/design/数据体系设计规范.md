## 1. 数据体系总览

### 1.1 使命

> **把 A 股市场的公开数据，沉淀为一份本地私有、可持续更新、可交叉分析、可 AI 增强的数据资产。**

与颜色体系的"品牌一致性"定位不同，数据体系是**平台价值的底座**：前端七个栏目的每一个画面，最终都来自这里某几张表。

### 1.2 分层架构

```

└───────────────▲──────────────────────────▲─────────────────────┘
                │ REST /api/*（9 模块）      │ 只读 SELECT
┌───────────────┴──────────────────────────┴─────────────────────┐
│  服务层  FastAPI backend/app                                    │

└───────────────▲────────────────────────────────────────────────┘
                │ 写表
```

## 3. 采集作业体系

### 3.1 运行架构

```
task_config（12 行，enabled/cron/params 可在前端热改）
   │  APScheduler（Asia/Shanghai，coalesce+max_instances=1+misfire 1h 补跑）
   ▼
run_task(name) ── TaskRecorder 记录 task_runs（running → success/failed + 写入条数）
   │
   ▼
collectors/*.py（实现类）→ pymysql 写表
```

- **运行中保护**：同任务 2 小时内已有 `running` 记录则拒绝新触发，防并发双写
- **失败策略**：全失败 raise → 任务 failed；部分失败（有成功写入）→ warning 但任务记 success
- **幂等**：INSERT IGNORE / TRUNCATE 重建 / 最小行数护栏（快照 <1000 行拒绝覆盖）

## 7. 治理原则（新增资产必须遵守）

1. **登记优先**：新增表/字段必须同步更新本文档 §2.2 清单（表注释写进 DDL）
2. **实现优先于配置**：`task_config` 只允许登记**已在 TASKS 注册**的任务；未实现任务一律 enabled=0，杜绝"看起来在跑"
3. **源必留痕**：每个采集器 docstring 必须写数据源接口与降级策略；每个数据域标注来源
4. **幂等是底线**：所有写表必须可重跑（INSERT IGNORE / 唯一键 / TRUNCATE 重建）
5. **读取不写**：网页层只读；任何写/改/删只允许发生在 MySQL 客户端或采集器内
6. **密钥不落库**：API Key 一律环境变量（当前 `ARK_API_KEY` 已规范，待重新申请激活）
7. **指标可复算**：分析 SQL 的每个数字要能追溯到源表（避免"死数字"）

- ⚠️ **维护纪律（v2.0 起）**：种子脚本是 `dq_rules` 的**唯一事实来源**。任何绕过脚本的直改 DB（如事故应急调阈值）必须同步回脚本，否则下次跑 seed 会把手改静默覆盖（2026-09-13 已实际发生：concept_market 两条规则 09-12 手调阈值被 09-13 的 seed 还原成旧值，导致 `concept_market_rows` 变红，已同步修复）
- 建表脚本 `backend/scripts/init_dq_tables.py`；启停热生效（前端规则配置 / `PUT /api/dq/rules/{rule_name}`）
- **分组执行（v1.9）**：`dq_rules.rule_group` = `daily`（v2.2 起 64 条，其中 63 条启用 + 1 条待启用；每日 20:30，最新切片类秒级）/ `weekly`（5 条，周一 21:30，全史窗口扫描约 6.4 分钟）；两轮均写同一 `dq_report`，按 `run_at` 区分轮次
- 13 类检查器：`freshness_daily`（对齐交易日历）/ `freshness_interval`（高频流间隔）/ `date_floor`（事件窗口下限）/ `row_count_slice`（最新切片行数）/ `row_count_total`（全表行数护栏）/ `null_rate_slice`（空值率）/ `violation_count`（最新切片自定义 where 脏值数）/ `where_count`（全表任意条件行数，静态档案表用，v1.4 新增；v1.9 起亦用于全史 OHLC / 涨跌幅衔接）/ `regex_count`（代码格式）/ `unique_index`（自然键唯一索引存在性）/ **`gap_scan`（全史疑似缺口，LAG 窗口）/ `source_handoff`（跨源衔接一致性）/ `per_key_coverage`（近端每票覆盖率）**（后三类 v1.9 新增）
