## 二、目标与范围

### 2.0 使用场景与节奏（**为什么这么改** —— 不是背景，是取舍判据）

> 本节承接《需求文档_金融使用视角》§1.1~§1.3。**执行时遇到取舍，以本节为准。**
> ⚠️ 前置说明：**本节的 `S1~S4` 是「使用场景」，与 §2.3 的「成功判据」不是一回事**（§2.3 已改用 `G1~G5` 编号避免混淆）。

**使用者**：A 股宏观 / 策略研究者。关心的不是「某指标是多少」，而是**方向**（钱变松还是变紧）、**环节**（是央行收、银行间贵、信用派不出、还是外部抽水）、**落点**（对 A 股流动性与风格意味着什么）。**只看结论与证据，不做数据核对。**

| 场景 | 时机 | 时间预算 | 页面行为 |
|---|---|---|---|
| **S1 晨会前速览** | 每交易日 8:45 | **30 秒** | 打开 → **只看首屏** → 记住一句结论 |
| **S2 异常归因** | 盘中/盘后异动（债跌 / 汇率异动 / 银行股异动） | 数分钟 | 打开 → **按环节定位** → 看那一段明细 |
| **S3 月度策略** | 月度策略会前 | **10 分钟** | 看趋势块与横向对比，**而非单点** |
| **S4 跨市场联动** | 美联储议息 / 美元异动时 | 数分钟 | 看外部约束 + 国内环节的**联合读数** |

**这四个场景覆盖 95% 的打开行为。** 两个直接推论 —— **本方案的所有结构改动都由它们推出，不是设计偏好**：

| 观察 | 推论 | 对应需求 |
|---|---|---|
| S1 只花 **30 秒** | ⇒ **结论必须不滚动可见**（否则 30 秒全花在滚动上） | R1 → P1 |
| S3 要花 **10 分钟** | ⇒ **证据必须可展开、可查**（不能为了短把明细删掉） | R5 → P4 |
| **同一页服务两种节奏（30 秒 / 10 分钟）** | ⇒ 「结论先行 + 明细默认折叠」是**唯一解**，不是偷懒 | R1 + R5 |
| S2 要**按环节定位** | ⇒ 必须有**页内锚点**直达某环 | R6 → P1 |
| S4 要**外部 + 国内联合读数** | ⇒ 外部约束不能埋在数量块里 | R2/R3 |

> 🔴 **给执行者的纪律**：任何与本方案字数/像素目标冲突的取舍，**回到本表判断** ——
> S1 场景下「多滚一屏」的代价 = 30 秒预算被吃掉 20%；S3 场景下「少一块证据」的代价 = 无法复核。
> 两者都不可接受 ⇒ 才需要「默认折叠但可完整展开」。

### 2.2 范围界定

**做**：
- 结论前置（Q1 上页头）
- 四环结构（Q2~Q5 各有独立落点 + 自上而下的传导顺序）
- 契约补齐（让卡片墙能承载新切面）
- 明细折叠（证据层默认收起）

**不做**（明确排除，防过度设计 —— 逐条对应《金融使用视角需求文档》§五）：
- ❌ 拆成多个独立子页（会切断流动性的交叉验证链：看「M2 涨」→ 跳价格页 → 跳外部页，**来回 3 跳**才能完成一次推理）
- ❌ 新增数据源 / 新表 / 新采集器（数据层本轮已落地并 DQ 守护，本次**纯前端 + 契约字段**）
- ❌ **做预测 / 给点位** —— 🔴 本模块管的是**「因」**（流动性的给定条件）；**预测归策略层**，「资金温度」模块才管「果」。**新增任何「预计 / 目标点位 / 预测值」类字段都是越界**
- ❌ 给存量类指标（M2/M3/BIS）做「近一年分位」（单调上行 ⇒ 伪信号，纪律 8）
- ❌ **两处重复结论全文**（会造成信息重复与维护分叉）—— 底部 `mc-cross` 只做**交叉印证**，不复述 Q1 结论；原位置可留**精简入口**，不得放全文
- ❌ 改「货币流动性」与「资金温度」的领域边界（契约⑩ 已定稿）

新增两个判读生成函数，与现有 `_verdict_level/_verdict_expectation/_verdict_policy`（L1367/L1383/L1398）并列：

```python
def _verdict_quantity(quantity: dict) -> dict:
    """q4：钱有没有派生到实体？—— 判的是「增速方向」而非「同比为正」（四层同比实测全正但方向分化）

    🔴 tone 必须落在判读条枚举内（normal / opportunity / caution）：
       源值 quantity.reading.tone = 'mixed' **无对应 CSS 类** ⇒ 必须显式映射（见 §3.3）。
    """
    src = quantity.get("reading") or {}
    return {
        "headline": src.get("headline", ""),
        "detail": src.get("detail", ""),
        "tone": _to_card_tone(src.get("tone")),   # 'mixed' → 'normal'（或新增 mixed 类，见 §9 D5）
    }

def _verdict_external(external: dict) -> dict:
    """q5：外部在抽水还是送水？—— 美债曲线 / 中美利差 / 美元指数

    source tone = 'caution' 已落在枚举内，可直接透传（.ao-verdict--caution 已定义）。
    """
    src = external.get("reading") or {}
    return {
        "headline": src.get("headline", ""),
        "detail": src.get("detail", ""),
        "tone": _to_card_tone(src.get("tone")),
    }

_CARD_TONES = {"normal", "opportunity", "caution"}

def _to_card_tone(v, default: str = "normal") -> str:
    """把任意来源的 tone 收口到判读条三态，避免生成不存在的 CSS 类（静默降级为灰）。"""
    return v if v in _CARD_TONES else default
```

### 10.6 勘误：本轮**脚本自身**的断言 bug（「先怀疑断言」纪律的实际执行）

> 本轮共出现 **3 次「脚本报 FAIL 但产品无误」**，全部按纪律先查断言、后查代码，逐条查实后修正断言。**记录下来以免重犯**。

| # | 表面症状 | 真因（脚本侧） | 修法 |
|---|---|---|---|
| ① | D4「锚点点击后目标不在视野」5 个全 FAIL，且 `hostScrollTop` 恒为 0 | 页面有 **3 层** `.n-layout-scroll-container`，`querySelector` 取到的是**不滚动的外壳**（scrollHeight=1120）；真宿主是第 2 层（scrollHeight=5507）。产品代码 `scrollIntoView` 完全正确（点击后目标 `top=12` = `scroll-margin-top`） | 复位与取值一律改用「scrollHeight 最大的 overflowY:auto 容器」；并加「复位后真宿主确已归零」前置断言 |
