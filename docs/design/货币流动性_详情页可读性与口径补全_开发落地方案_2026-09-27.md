#### B1｜`region` × `market` 两轴字段（16 项全覆盖）

#### B4｜R14-4 条件显示（**提到 P1**，因为它决定分母）

```python
CURVE_ANOMALY_BP = 5.0   # R14-4 门槛（只认凹陷方向，见下方 v2.6 修订）

def _curve_anomaly(curve: list[dict]) -> dict:
    """四期限是否出现「中间期限异常**凹陷**」（R14-4 条件显示 · 方案 A）。

    判据两条**同时成立**才算异常：
      ① 曲线非单调（非 ON < 1W < 1M < 3M）；
      ② **凹陷方向**存在中间期限相对两端线性插值低于门槛（取凹陷最深者）。
    """
    vals = [c["cur"] for c in curve]
    if any(v is None for v in vals):
        return {"is_anomaly": False, "term": None, "dev_bp": None, "all_devs": {}, "text": ""}
    devs = {}
    for i in (1, 2):                                   # 1W / 1M
        exp = vals[0] + (vals[-1] - vals[0]) * i / (len(vals) - 1)
        devs[curve[i]["term"]] = round((vals[i] - exp) * 100, 1)
    mono = all(vals[i] < vals[i + 1] for i in range(len(vals) - 1))
    dips = {t: d for t, d in devs.items() if d < 0}    # ← 只认凹陷（排除跨月末凸起）
    if mono or not dips:
        return {"is_anomaly": False, "term": None, "dev_bp": None,
                "all_devs": devs, "text": ""}
    worst_term, worst_dev = min(dips.items(), key=lambda kv: kv[1])
    hit = worst_dev < -CURVE_ANOMALY_BP
    return {"is_anomaly": hit, "term": worst_term if hit else None,
            "dev_bp": worst_dev if hit else None, "all_devs": devs,
            "text": (f"{worst_term} 相对曲线两端凹陷 {abs(worst_dev)}bp"
                     f"（>{CURVE_ANOMALY_BP:g}bp），曲线非单调 —— 该期限资金淤积，"
                     f"存在供给或考核约束" if hit else "")}
```

## 六、验收方案

> 🔴 **总纪律（本项目既有教训，逐条执行）**
> 1. **每条验证命令必须先做负对照**：故意植入一个必然报错的探针，确认命令会 `EXIT ≠ 0`，再删掉探针取干净基线。

2. **`term_spread` ⚠️（登记 ①）** —— ③ 段以**负面**收尾（"去杠杆先砸高波动品种"），而影响句给**正面**。

   ⇒ 属"可接受但不完整"。**建议**（同属 R12.3 文案改动，需确认）：③ 段末补一句"同一成本上升也压缩债市杠杆套息的利差空间"。

#### 勘误 ⑪：**响应体红线口径由「单看未压缩字节」改为「原始 ＋ gzip 双线」**

P2 定的红线是 `A24 / AP2-19`：响应体 **≤ 90 KB**。P3 铺满 16 条后实测 **113.8 KB** ⇒ **FAIL**。
定性：这是**度量口径问题，不是性能问题** —— 实测该响应体 **gzip 后仅 20.3 KB（压缩率 18%）**，而中文文案（`hint_parts` 占 14.9 KB）压缩率远高于结构化数字。

| 口径 | 实测 | 判定 |
|---|---|---|
| 未压缩原始字节 | 113.8 KB | ⛔ 超 90 KB 线（但**线本身选错了**） |
| **gzip 传输字节** | **20.3 KB** | ✅ 真实网络开销，量级很小 |

**修法**：红线改为「**≤ 120 KB 原始 且 ≤ 25 KB gzip**」（`_verify_p2.py` 的 `AP2-19` 与 `_verify_scope_p1.py` 的 `A24` 同步；需求 §六排除表与附录 A24 相应对齐）。
**为什么保留原始字节数**：它是**序列化开销**（后端 CPU）的代理，与本项目 `ttl_cache(600)` 的缓存命中率直接相关，不能只看传输量。
⇒ **纪律**：**红线指标必须先确认它度量的是什么** —— 一个为"网络卡顿"设的线，不该用"后端序列化字节数"来卡（两者在中文场景可差 **5.6 倍**）。

#### 勘误 ⑫：`_impact_lpr()` 首版**真 bug** —— "未动"被误判成"刚调整"（**静默，且与 `status` 当场矛盾**）

`AP3-3` 首次运行即 FAIL：`lpr` 期望"中性"、实得"正面影响"。**这不是断言错，是实现错。**

| 面 | 修正前 | 修正后 |
|---|---|---|
| 判"未动"的依据 | `cur != prev`（`prev` = **上一次不同取值**） | `idle_months == 0`（本月刚调整） vs `>= 1`（未动） |
| 症状 | 当前值已静止 **16 个月**，但 `prev` ≠ `cur` **恒成立** ⇒ 永远判成"刚调整过" ⇒ 输出"正面影响" | `idle_months=16 ⇒ 中性` ✅ |
| 与之并列的 `status` | 「已连续 16 个月未动」 | 不变 |

⇒ **`status` 说"未动"、`impact` 说"正面影响"**，同一张卡上两句话**当场打架**，且**不报任何错**。
**根因**：`lpr.prev` 字段的语义是"**上一次不同取值**"（政策利率是台阶状的，没有"上一交易日值"这一说），而首版实现按"上一期值"去理解它 ⇒ **字段语义误读**。
**修法**：改判 `idle_months`（口径与 `status` 的"已连续 N 个月未动"**同源**），并把该坑写进 `_impact_lpr` 的 docstring。
⇒ **纪律**：**同一张卡上的两句话若由两个字段各自推导，必须核对"是否引用同一时间基准"** —— 否则会生成"自相矛盾且静默"的展示。

#### 勘误 ⑭：**参考线标签 `position: 'end'` 会被画到网格外、被裁掉**（**截图才发现**，纯视觉、不报错）

第一版按 §F6 的写法给了 `label.position = 'end'`。**接口/断言全绿**，但截图里右端只剩「`3M…`」——
`grid.right` 仅 **16px**，而标签「3M 近一年中位 1.509%」约 130px 宽 ⇒ **整段画到网格右边界之外被裁**。

| 面 | 值 |
|---|---|
| 修法 | `position: 'end'` → **`'insideEndTop'`**（echarts 语义：端点处、文字在线段**上方**、且保持在**图形内部**） |
| 为什么断言没抓到 | 当时断言只查 `label.show === true` 与文本内容，**没查位置** ⇒ 新增 `label.position` 必须以 **`inside` 开头** 的断言（canvas 文字量不到像素，退而断言配置位是可得的最强证据） |
| 复验 | 实例 `label.position = insideEndTop`；**1x 原分辨率**紧裁特写（`p4_4_ref_label_zoom.png`）确认标签完整、位于虚线上方、无重叠 |

⇒ **纪律**：**文字类改动的"绿色断言"证明不了"看得见"** —— `show: true` 与 `formatter` 正确，仍可能被裁到画布外。凡新增图上文字，**必须补一张紧裁截图**。

#### 勘误 ⑯：**naive-ui 折叠未展开时 DOM 里根本没有内容**（`textContent` 也读不到）

`DP4-9` 首跑：`document.querySelectorAll('.mc-scope-body p')` 命中 **0** —— 不是选择器错，是 **`NCollapseItem` 未展开时不挂载子节点**。
连改成 `textContent` 也无效（元素不存在）。**必须先展开折叠**，且按既有纪律用 `ElementHandle.click()`（`el.click()` 进不了组件层事件）。

> ⚠️ 与 P2 踩过的那条**不同**：P2 是"折叠内容**在** DOM 里但 `innerText` 因 `display:none` 返回空串"（P3 五段浮窗那类）；P4 这条是"**根本不在** DOM 里"。
> ⇒ 断言折叠内文案前，先断言**元素数量 > 0**，再断言内容 —— 否则"0 是空"与"0 是不存在"会被混为一谈。

#### 勘误 ⑰：**echarts 实例没有挂 `window.echarts`，但可以走 `vue-echarts` 的 `expose` 拿到**（本轮最有用的技术发现）

本项目按需引入 echarts（`echarts/core`），**不注册全局** ⇒ `window.echarts.getInstanceByDom(el)` 这条路不存在。
但 `vue-echarts` 内部 `expose({ setOption, chart, ... })` ⇒ 可从 DOM 反查 Vue 组件实例：

```js
const host = document.querySelector('#mc-trend .echarts-host')
const ch = host.__vueParentComponent.exposed.chart     // ← 真的 echarts 实例
const o = ch.getOption()                              // ← 实际生效的 option
o.yAxis[0].min                          // 1.2
o.series.map(s => s.markLine?.data)     // 逐序列 markLine
ch.convertToPixel({ yAxisIndex: 0 }, 1.509)  // 值 → 像素 y（取景也靠它）
```

**为什么这条重要**：它把"**断言 prop 传对了**"升级成"**断言 echarts 真的吃进去了**" ——
`min` 可能被 nice 化、`markLine` 可能被丢弃、`label` 可能被裁，**读 prop 全看不出来**。
P4 的 DP4-4/5/6/7 全部走实例实读。

> ⚠️ 反例记录：`ch.renderToSVGString()` 试过**不可用** —— 它只支持 **SVG 渲染器**，本项目是 CanvasRenderer，
> 调用直接抛 `renderToSVGString can only be used in the svg renderer`。⇒ 想"用 SVG 读文字坐标"这条路在本项目**不通**，
> 图上文字的可见性只能靠**紧裁截图 + 配置位断言**两个手段合起来证。

> 💡 **取景教训**（承接 P3 勘误 ⑬ 那条）：`Read` 工具会**降采样**大图 ⇒ 1x 全卡截图里"参考线像穿过标签"是**假象**，
> 3x 放大与 1x **紧裁（200×36）** 都显示标签干净地在上方。⇒ **判断"图上小字是否清晰/是否被压"必须用紧裁或放大，不能用整图目测**；
> 取景坐标优先用 `chart.convertToPixel(值)` 换算，不要靠比例估算（首版按比例取景直接**拍空**）。
