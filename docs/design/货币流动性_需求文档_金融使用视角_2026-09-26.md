## 一、我是谁、我什么时候用它

### 1.1 使用者画像

**我是 A 股宏观 / 策略方向的研究者。** 我关心的不是「某个指标是多少」，而是：

- **方向**：现在钱在变松还是变紧
- **环节**：如果是变紧，是央行收、银行间贵、信用派不出、还是外部抽水
- **落点**：这件事对 A 股（尤其流动性与风格）意味着什么

我不做数据核对，数据由你们采集与守护（DQ 已覆盖）。**我只看结论和证据**。

### 1.2 四个真实使用场景

| 场景 | 什么时候 | 我想问的 | 我在页面上的行为 |
|---|---|---|---|
| **S1 晨会前速览** | 每交易日 8:45 左右，5 分钟 | 今天流动性要不要关注？ | 打开 → **只看首屏** → 记住一句结论 |
| **S2 异常归因** | 盘中或盘后出现异动（债跌 / 汇率异动 / 银行股异动） | 是流动性收紧导致的吗？**是哪个环节**？ | 打开 → 按环节定位 → 看那一段的明细 |
| **S3 月度策略** | 月度策略会前 | 当前流动性水位 vs 半年 / 一年前，处在什么状态？ | 看趋势块与横向对比，而非单点 |

## 二、为什么这 5 个判断句需要「一条链」而不是「一堆指标」

这是本次需求**唯一需要工程侧理解的专业前提**。理解了它，§四 的所有需求都是自然推论。

### 2.1 货币流动性是一条单向传导链

货币流动性在金融学上**不是一组平行指标，而是一条有序的传导链**：

```
① 央行操作  →  ② 银行间定价  →  ③ 信用派生  →  ④ 对外与资产
（政策与投放）  （资金价格）      （货币存量）     （全球边界条件）

央行投放基础货币 → 决定银行间资金价格 → 价格决定派生意愿 → 派生结果决定广义货币
                                        ↑
                            ④ 外部条件贯穿全程（汇率、海外利率、离岸美元）
```

| 环节 | 金融含义 | 这一环回答的问题 | 判别它的读数 |
|---|---|---|---|
| **① 央行操作** | 基础货币的**投放 / 回笼动作** | 央行在放还是在收？ | 中国 OMO（逆回购 / 买断式）· 美联储总资产 · TGA · ON RRP |
| **② 银行间定价** | 资金在**金融体系内**的价格 | 钱现在贵不贵？ | Shibor 隔夜 / 1W / 1M / 3M · 期限利差 · LPR |
| **③ 信用派生** | 基础货币被**派生为广义货币** | 钱有没有派生到实体？ | 美国 M2 · 欧元区 M3 · 中国 M2 / M1 / M0 · 剪刀差 |
| **④ 对外与资产** | 全球**边界条件**（外生给定） | 外部在抽水还是送水？ | BIS 境外美元信贷 · 中国外储 / 黄金 · 美元指数 · 中美利差 · 美债曲线 |

### 2.2 单指标为什么无意义 —— 交叉验证是专业价值所在

这是我坚持「不要拆成 5 个独立页面」的**专业理由**，请工程侧务必理解：

| 如果我只看到 | 我会误判成 | 真相可能是 |
|---|---|---|
| 资金价格低（②） | 「宽松」 | 也可能是**需求萎缩**，没人借钱 |
| M2 涨（③） | 「主动宽松」 | 也可能是**被动派生**（财政投放、汇率占款） |
| 央行缩表（①） | 「收紧」 | 也可能**同时**外资流入（④），对 A 股反而是宽松 |

⇒ **任何单一环节的读数都不能单独成结论**。正确形态是：

> **分环节独立推理 + 一张合并结论 —— 两者缺一不可。**

而现状是**两头都缺**：分环节的卡只有 1 个读数（推不出结论）、合并结论躺在第 5.2 屏（看不到）。这正是 R1 + R2 + R3 要一起解决的事。

### 2.3 五个判断句 → 四环 → 现有数据 的完整映射

**好消息：数据一个都不缺，全部已经在库里、已经接进接口。** 本次需求**纯信息架构**，不新增采集。

| ⑤判断句 | 环节 | 现有读数（已在接口） | 现页面位置 |
|---|---|---|---|
| Q1 | 全链汇总 | 四层同比方向的同向判定（现 `tone = mixed`） | `mc-cross` 块（**第 5.2 屏**） |
| Q2 | ① 央行操作 | 中国 OMO（逆回购 / 买断式，分栏目）· 美联储总资产 · TGA · ON RRP | 分散在 `mc-quantity` 的美国层 / OMO 子块 |
| Q3 | ② 银行间定价 | Shibor 3M 水平与分位 · 期限利差（3M − 隔夜）· LPR 1Y · 三条 Shibor 时序 · 期限结构表 | 页头 5 KPI + `mc-curve` + `mc-trend` + `mc-lpr` |
| Q4 | ③ 信用派生 | 美国 M2 · 欧元区 M3 · 中国 M2 / M1 / M0 · M2 结构 · 剪刀差 | 埋在 `mc-quantity` 的各国层里 |
| Q5 | ④ 对外与资产 | BIS 境外美元信贷 · 中国外储 / 黄金 · 美元指数 · 中美利差 · 美债曲线 | `mc-external` + `mc-quantity` 的全球层 / 中国外储 |

> **诊断结论**：现在的 `mc-quantity` 块是**按数据表**切的（BIS 一张表 / 美联储三张表 / 美欧中各一张 = 四个块），
> 结果一个块里混了 **①央行操作 + ③信用派生 + ④对外**三个环节，而 ③ 反而没有独立单元。
> **这是「看着乱」的结构性来源 —— 不是排版问题。**

### R1｜结论先行 🔴 最高优先级

**我要什么**

打开页面，**不用滚动**就能读到一句 Q1 的答案。例如：

> 「**四个环节两扩两缩，流动性方向不明 —— 美国流动性改善、中国边际收紧。**」

**为什么**

S1（晨会前 5 分钟）是本页最高频的使用场景。让我滚 5 屏才看到结论，等于这页在最需要时不可用。
**结论先行的本质是：先给判断，再给依据** —— 这是研究报告的标准写法，也应是这一页的写法。

**达标判据**

| 类型 | 判据 |
|---|---|
| 使用者 | 打开页面，**首屏（不滚动）** 能读到结论句 |
| 可量测 | 结论区 `boundingBox.top < 视口高`（**从 `page.viewport()` 取值，勿写死 1120**；现为 5830） |
| 内容质量 | 结论句必须**含方向词**（偏松 / 偏紧 / 分化），不能只是「各环节如下」 |
| 保留 | 原位置可以**留一个精简入口**（如「详情见文末」链接），但**不得两处重复全文** |

### R2｜四环独立：把「数量」拆回传导链 🔴 高优先级

**我要什么**

详情页按**四环**分区，每环一个独立单元、自带该环的结论句：

```
① 央行操作    → 一句话：央行在放还是在收（Q2）
② 银行间定价  → 一句话：钱贵不贵（Q3）
③ 信用派生    → 一句话：派生强不强（Q4）
④ 对外与资产  → 一句话：外部抽水还是送水（Q5）
```

**为什么**

这是本次最核心的金融诉求。指标的价值取决于**它在链条上的位置**：

- 「美联储缩表」和「中国 M2」在数据上是两张表，在分析上是**两个不同环节**（① vs ③）
- 「OMO 操作量」和「M2 增量」都在 `mc-quantity` 里，但一个是**流量动作**（①）、一个是**存量结果**（③）—— 混在一起我无法归因

⇒ **区块边界要按因果位置划，不按数据源划。**

**达标判据**

| 类型 | 判据 |
|---|---|
| 使用者 | 我能直接问「是哪个环节出问题」并**只滚到那一段**就得到答案 |
| 可量测 | 详情页存在 **4 个语义化分区**，每个分区有①独立标题（含环节名）②**该环的一句话结论**③该环明细 |
| 归属正确性（逐项核） | 美联储三腿 / OMO → **①**；Shibor / 期限利差 / LPR → **②**；美 M2 / 欧 M3 / 中 M2 → **③**；BIS / 外储 / 美元指数 / 中美利差 → **④** |
| 不重叠 | 任一读数**只出现在一个分区**（现「美联储三腿」与「M2」同在数量块，须拆开） |

### R3｜五个判断句全部上墙 🟠 高优先级

**我要什么**

总览页卡片墙上，「货币流动性」这一组能看到 **Q1~Q5 的答案**（现在只有 3 张卡，且全是价格侧）。

**为什么**

总览页是我**最先看到**的页面。**总览页看不到的切面，等于不存在。**

现状：详情页 5 切面 vs 卡片墙 3 卡 —— 我上个月落地的 7 个数量读数（14.75 / 5.80 万亿等）在总览页**完全不可见**，这是我 D1 决策的直接后果，也是当前最大的信息缺口。

**达标判据**

| 类型 | 判据 |
|---|---|
| 使用者 | 在总览页「货币流动性」组内，我能看到「钱多不多（数量）」与「外部约束」的读数 |
| 可量测 | 卡片墙该组**卡数 3 → 5**，其中至少 1 张卡承载 **≥4 个数量读数** |
| 金融正确性 | 新增的「数量」卡必须**混装四个环节的代表读数**（每环 ≥1 个），否则又变成数据表投影 |
| 密度对齐 | 新增卡的信息密度应接近相邻组（「市场风向」3 卡 6 读数 ≈ 每卡 2）；现「货币流动性」3 卡仅 3 读数 |

> ⚠️ **实现提示（详见面向前一版文档 §二 · 2.4）**：卡片墙当前**只读 `kpis` 一个字段**，
> `quantity_kpis` / `external_kpis` 是独立数组、**不被读取**；且过滤为空时存在**静默回退**，
> 会让新卡显示成别的切面的读数。这两点是**「不报错但内容错」**，实现时必须处理。

### R4｜美 / 欧 / 中 横向对比 🟠 中优先级

**我要什么**

中国 M2 不要孤立展示，改为**三经济体横向对比**（可含同比条形 / 增速差异），让我一眼看到分化。

**为什么**

- 中国 M2 **52.87 万亿** vs 美国 **23.34 万亿** vs 欧元区 **20.00 万亿** —— 信息在**差值**里，不在单值里
- 孤立读数无法回答「谁的流动性在扩张更快」这个策略判断的起点

**🔴 专业硬约束（必须遵守）**：横向对比**必须标注汇率与计价口径** ——
中国 M2 折美元用 **6.7489**（USD/CNY 中间价）、欧元区用 **1.1355**（EUR/USD）、BIS 原为百万美元。
**不标口径的跨国对比会随汇率漂移而失真**，这在上一轮已踩实过。

**达标判据**

| 类型 | 判据 |
|---|---|
| 使用者 | 我能读到「美 / 欧 / 中」三个数**在同一视野内**，并看到相对关系 |
| 可量测 | 三经济体 M2/M3 出现在**同一区块**（现分属 3 个块） |
| 口径 | 页面**明示**折算汇率与单位；单位统一为**万亿美元** |

> ## 🟠 补充（2026-09-26 全栈评审 · 实码复核）
>
> 实测接口 `fx` 段 = `{'usd_cny': 6.7489, 'eur_usd': 1.1355, 'source': 'currency_boc_daily（人民币中间价…）'}`
> —— **汇率本身没有 `as_of`**。而本页各源时间轴不同（BIS 季度、美欧 M2 月度、美联储周度；
> 实测顶层 `as_of=2026-09-24`，`quantity` 内美联储为 `2026-09-23`）。
>
> ⇒ 页面能显示「1.1355」，但**无法回答「这是哪天的汇率」**，横向对比是否失真**无法被复核**。
> **R4 落地时必须给 `fx` 补 `as_of`**（或明确写入「取数日 = 请求日」的约定）并随数字渲染。

### R5｜结论与证据分层（明细默认折叠） 🟡 中优先级

**我要什么**

把「证据级」内容（BIS 分腿明细 / OMO 逐笔 / M2 结构表 / 期限结构全表）**默认折叠**，需要时点开。

**为什么**

S1（30 秒）与 S3（10 分钟）**共用同一页**：

- S1 只要结论 → 明细展开就是在**制造滚动成本**
- S3 要证据 → 明细要**可展开、可查**

⇒ 默认折叠是**同时满足两种节奏**的唯一解，不是偷懒。现页面 6176px 中，`mc-quantity` 2839px 里有大量是证据级明细（中国块 1273px 尤其）。

**达标判据**

| 类型 | 判据 |
|---|---|
| 使用者 | 打开页面时**看不到**逐笔 / 全表；需要时能一键展开 |
| 可量测 | 默认视图页面总高**显著下降**（目标 ≤ 约 3500px，即 3 屏内）；折叠项可展开且内容完整 |
| 不牺牲 | 折叠不得丢失信息 —— 展开后与现在完全一致 |

> ## 🟡 补充规则（2026-09-26 全栈评审 · 与 R6/anchor 的冲突）
>
> 7 张数量 KPI 卡的 `anchor` 指向 `mc-qty-global/us/eu/cn`。若把这些区块**默认折叠**，
> 点击卡片后 `scrollIntoView` 会滚到一个**折叠体内不可见的目标**（元素存在但内容不展开）⇒ 用户看到「跳到了空白」。
>
> **规则（建议 A）**：
> - **A（推荐）**：**含 anchor 目标的区块不得默认折叠** —— 折叠只用于「无 KPI 指向」的纯证据块（如 OMO 逐笔、M2 结构表）；
> - B：跳转前先自动展开目标区块（需额外状态同步，成本更高）。

### R6｜页内锚点导航 🟡 中优先级

**我要什么**

页头提供 **4 个环节锚点**（① 央行操作 / ② 银行间定价 / ③ 信用派生 / ④ 对外与资产），点一下直达。

**为什么**

S2（异常归因）要**快速跳转**到某一环。5.5 屏的页面没有导航，等于每次归因都要滚一遍。

**达标判据**

| 类型 | 判据 |
|---|---|
| 使用者 | 我能在页头看到 4 个环节入口，点击后**该区块进入视野** |
| 可量测 | 存在 4 个锚点；点击后目标区块 `top` 落在视口补偿区间（0~40px） |

> ## ✅ 实现指引已更正（2026-09-26 全栈评审 · 实机量测）
>
> 前一版工程附录 §5.2 曾写「`scrollIntoView()` 对滚动容器**无效**，必须直接改 `scrollTop`」——
> **该结论已被实机量测推翻**（详见《需求评估报告_全栈开发视角》§三 B2）：
>
> ```
> 点击前  #mc-qty-global top = 3632   容器 scrollTop = 0
> 点击后  #mc-qty-global top = 0      容器 scrollTop = 3632   window.scrollY = 0
> ```
>
> **正确做法：直接复用现有 `KpiCards.vue:81` 的 `goAnchor()` 模式** ——
> `el.scrollIntoView({ behavior: 'smooth', block: 'start' })` + 目标元素 `scroll-margin-top: 12px`
> （5 个详情页均已如此配置，与全局一致）。**不要改 `scrollTop`**，否则会丢掉 `scroll-margin` 的顶栏补偿。
| 状态 | 当前所在环节有高亮反馈（可选） |
