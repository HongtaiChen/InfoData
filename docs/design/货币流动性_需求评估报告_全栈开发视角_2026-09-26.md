## 三、🔴 阻塞级发现（3 项，必须开工前修正）

### B1｜栅格预算算错：新增 2 卡会得到「一行挤扁」，而非「两行满格」

**原文档（工程附录 §5.1 / 前文）**：

> 5 张卡按「3 narrow + 1 narrow + 1 full = **24 列**」可**两行满格**（第一行 4 narrow，第二行 1 full）

**实码（`AnalysisOverview.vue:513-519`）**：

```css
.ao-cards { display: grid; grid-template-columns: repeat(var(--ao-cols, 12), minmax(0, 1fr)); gap: 12px; }
.ao-card--narrow { grid-column: span 3; }
.ao-card--half   { grid-column: span 4; }
.ao-card--full   { grid-column: span 12; }
/* 源码注释：「列数由组内卡片 span 之和决定（由 :style 下发 --ao-cols）⇒ 每行必定铺满，右侧不留空档」 */
```

且 `g.cols += SPAN_COLS[cardSpan(m)]` —— **cols 恒等于组内所有卡的 span 之和**。

⇒ **机制真相：cols = sum(span)，栅格列数 = cols ⇒ span 之和恒等于总列数 ⇒ 永远只有一行、且必定铺满。**
**不存在「换行」这一说。** 原文档的「两行满格」是把 `span` 当成固定 12 列栅格算的，与实码不符。

**照做的后果**（1440px 实算）：

| 方案 | cols | 每张卡宽度 | 结果 |
|---|---|---|---|
| 现状 3 narrow | 9 | 1344 × 3/9 ≈ **448px** | ✓ 舒适 |
| 原文档「4 narrow + 1 full」 | 24 | 窄卡 1344×3/24 ≈ **168px**；full 卡 ≈ 672px | ❌ **4 张被压扁到 168px**，标签+数值+状态+刻度条塞不下 |

**修正方案（推荐 · 零机制改动）**：

> **5 张卡全部用 `half` 档** ⇒ cols = 4×5 = **20**，每张 20% ≈ **269px**，**5 等分、一行铺满、整齐无残缺**。

附带两个好处：
1. `CARD_KPI_LIMIT.half = 3`（narrow 只有 1）⇒ 现有 3 张卡从「各 1 读数」提升到「最多 3 读数」，
   **正好一并修掉主文档 C-4「货币流动性 3 卡共 3 读数 vs 市场风向 6 读数」的密度差**；
2. 只改 registry 的 `card_span` 3 处 + 新增 2 卡，**不动全局栅格机制**，零回归面。

备选（不推荐）：若要保留「数量卡独占一行」的层次感，需改全局机制
（`--ao-cols` 排除 full 卡 + `.ao-card--full { grid-column: 1/-1 }`），
**会影响其余 4 个组**，必须整组回归，风险与收益不匹配。

**验收**：5 张卡 `boundingBox.width` 两两偏差 ≤ 2px，且 `sum(width)+gap×4 ≈ 容器宽`（无右侧空档）。

### B2｜锚点实现指引错误：`scrollIntoView()` 实测有效

**原文档（工程附录 §5.2）**：

> 🔴 滚动定位（R4 锚点导航，naive-ui 陷阱）：**不能用** `element.scrollIntoView()` ——
> 滚动宿主是 `.n-layout-scroll-container`，**必须直接改其 `scrollTop`**。

**实机量测（`_scratch/_probe_scroll_who.js`，两轮交叉验证）**：

```
点击前  目标元素 #mc-qty-global top = 3632   容器 scrollTop = 0
点击后  目标元素 #mc-qty-global top = 0      容器 scrollTop = 3632    window.scrollY = 0
滚动主体：div.n-layout-scroll-container（唯一变化者）
页面错误：0
```

**判定**：
- ✅ `scrollIntoView({behavior:'smooth', block:'start'})` **完全有效**，能驱动该容器滚动 3632px；
- ✅ `scroll-margin-top: 12px` **同样生效**（目标最终停在 top∈[0,40] 的补偿区间）；
- ✅ 该实现**已在生产使用**：`KpiCards.vue:81` 的 `goAnchor()` 就是它，且**5 个详情页全都配了** `scroll-margin-top: 12px`
  （`MarketWindView.vue:327` 注释原文：「KPI 卡点击滚到锚点时留出顶栏高度，避免卡片标题被顶栏遮住」）。

**若照原文档改为直接改 `scrollTop`**，会：① 丢掉 `scroll-margin-top` 补偿 ⇒ 目标标题被顶栏遮住；
② 与其余 4 个详情页的实现分叉，制造两份需要同步维护的逻辑。⇒ **属反向劣化。**

**修正**：R6 的锚点导航**直接复用 `goAnchor()` 的同一模式**（`scrollIntoView` + 目标元素 `scroll-margin-top`），
并把这条从「陷阱」改判为「**既有可用实现，照抄即可**」。

> ⚠️ 该错误结论同时存在于我的本地技能 `frontend-shot-puppeteer`（gotcha #6b），
> **已一并修正** —— 教训：**把一次特定场景的观察泛化成「普遍无效」是危险的**，
> 这条 gotcha 当时并未做「负对照」（即未验证同一个 `scrollIntoView` 在正常路径下是否有效）。

### B3｜R1 落点选错：`mc-cross` 不是 Q1 总判断，且详情页根本没渲染总判读

**两条独立证据**：

**证据 1 —— `mc-cross` 的语义不是 Q1**（`MoneyCostView.vue:1023-1043`）：

| 区块内子卡 | 数据源 | 实际回答 |
|---|---|---|
| `政策 vs 市场` | `policyMarket.reading` | 政策利率与市场资金价格**是否同步** |
| `资金 × 权益位置` | `equityCross.reading` | 资金价格与权益位置**是否互证** |

⇒ 它是**因果验证**（两个模块的交叉印证），属「证据」层；而 Q1「现在钱松还是紧」是**总判断**。
把 `mc-cross` 搬去页头 = **页头放印证细节，而总判断仍然缺失**。

**证据 2 —— 详情页完全没渲染 `verdict`**：
`grep -n "verdict" views/analysis/MoneyCostView.vue` ⇒ **零命中**。
而后端**早已下发**：`verdict = {headline: "资金价格偏松（近一年 38% 分位）、期限结构偏平坦（24% 分位）", detail, tone}`。

⇒ **痛点确认（R1 需求成立）**：详情页确实没有一句总判读。
⇒ **但修法更简单**：在页头渲染后端**已有**的 `verdict.headline`（Q1 价格侧）+ 四环方向判定（Q1 汇总侧）。
**零后端改动、零契约连锁**，纯前端模板 + 接线。

**修正后的 R1 定义**：

| 项 | 内容 |
|---|---|
| 位置 | 参数区之后、第一条 KPI / 区块之前（首屏内） |
| 数据源 | `verdict.headline`（已有）+ 四环方向汇总（`quantity.reading` 已算，可复用其判定逻辑） |
| `mc-cross` | **保留原位**（底部证据层），可加「交叉印证」小标题明确其层级 |
| 验收 | 结论条 `boundingBox.top < 视口高`（**不要写死 1120**，见 §八 建议 1） |

## 四、🟠 契约连锁遗漏（4 项 —— 漏一处就是「不报错的坏功能」）

### C1｜新增 track 卡必须同时补 `verdicts.q4 / q5`（原文档漏）

**实码**（`AnalysisOverview.vue:213`）：

```ts
const v = (m.question ? r?.verdicts?.[m.question] : null) ?? r?.verdict
```

⇒ 卡片墙的**判读条也按 `question` 取子判读**，取不到才回退模块级 `verdict`。
而实测 `verdicts` 只有 `['q1','q2','q3']`。

**后果**：新增 `q4`（数量）/ `q5`（外部）两张卡后，若不同时补 `verdicts.q4/q5`，
这 2 张卡的判读条会**回退到模块级 `verdict`**（= 「资金价格偏松…」）——
即**卡片问的是数量，判读条答的是价格**，且**不报错**。

**修正**：`verdicts` 必须扩到 `q1~q5`，且每条的**语义要与该卡 `question_text` 对齐**。

### C2｜新增卡的 KPI 必须标 `questions: ['q4'] / ['q5']`（原文档仅笼统提「标注」）

**实测**：`quantity_kpis` 7 个、`external_kpis` 4 个的 `questions` **全部为 `None`**。

**后果链**：前端先按 `questions` 过滤 → 全 `None` ⇒ **过滤结果为空** →
触发 `scoped.length ? scoped : kpis` 的**静默回退** ⇒ 卡上显示 `kpis`（Shibor/期限利差/LPR）**内容**。

**修正**：这是**必需字段**，不是可选优化。改造清单要明确写出：
后端为「数量卡」选的 6 个读数、为「外部卡」选的 3 个读数，**逐个打上 `questions` 与 `card_rank`**。
（另注 `pickCardKpis` 的**内层**副作用：只要有任一 KPI 带 `card_rank`，未标 `card_rank` 的会被整体丢弃 —— 故同卡内读数必须**全部**标 `card_rank`。）

### C3｜R2 改区块 id 必须同步 12 处后端 `anchor`（原文档漏，且失败是静默的）

**现状**：`anchor` 硬编码在**后端** `money_cost.py`（441/446/450/462/488/519/1173/1561/1568/1576/1584/1589 等），
模板侧 id 硬编码在 `MoneyCostView.vue`，两侧靠**字符串**约定，**无编译期校验**。

当前 9 类 id：`mc-curve` · `mc-trend` · `mc-lpr` · `mc-ext-curve` · `mc-ext-dxy` · `mc-qty-global` · `mc-qty-us` · `mc-qty-eu` · `mc-qty-cn`
（实测带 anchor 的 KPI 卡共 **16 张**）

**后果**（`KpiCards.vue:80`）：

```ts
function goAnchor(k: Kpi) {
  if (!k.anchor) return
  document.getElementById(k.anchor)?.scrollIntoView(...)   // id 不存在 ⇒ ?. 静默跳过
}
```

⇒ **改 id 忘改 anchor ＝ 点击卡片毫无反应、控制台零报错。**
这是本项目第 **3** 类「静默失败」（前两类：`questions` 回退、`verdicts` 回退）。

**修正（建议列为 P0 前置）**：R2 四环重排前，先把锚点做成**单一事实来源** ——
例如后端定义 `ANCHORS = {...}` 常量供 `anchor` 字段引用，模板 id 从同一常量导出；
退一步至少建立「anchor ↔ 模板 id」的**自动校验脚本**（扫描两侧字符串做集合比对，纳入验收）。

### C4｜`fx` 段没有 `as_of`，R4 的「口径可审计」无法满足（原文档漏）

**实测载荷**：`fx: {'usd_cny': 6.7489, 'eur_usd': 1.1355, 'source': 'currency_boc_daily（人民币中间价…）'}`

⇒ **汇率本身没有日期**。而主文档 R4 硬性要求「跨国对比必须标注汇率与计价口径」（这是上一轮踩实过的纪律）。

**后果**：页面能显示「1.1355」，但**无法回答「这是哪一天的汇率」**——
而 BIS 是季度、美国 M2/欧元区 M3 是月度、`as_of` 各不同（实测顶层 `as_of=2026-09-24`，
而 `quantity` 内各源 as_of 各异，如美联储 `2026-09-23`）。横向对比失真的风险**无法被复核**。

**修正**：`fx` 段补 `as_of`（或明确写入「取数日 = 请求日」的约定），随数字一起渲染。

## 五、🟡 需求间冲突与口径缺口（3 项）

### K1｜R5 折叠 × R6/anchor 跳转 冲突

7 张数量 KPI 卡的 `anchor` 指向 `mc-qty-global/us/eu/cn`。若 R5 把这些区块**默认折叠**，
点击卡片后 `scrollIntoView` 会滚到一个**折叠体内不可见的目标**（元素存在但内容不展示）⇒ 用户看到「跳到了空白」。

**规则（二选一，建议 A）**：
- **A**：**含 anchor 目标的区块不得默认折叠**（折叠只用于「无 KPI 指向」的纯证据块，如 OMO 逐笔、M2 结构表）；
- **B**：跳转前先自动展开目标区块（需要额外逻辑与状态同步，成本更高）。

### K2｜R3 加卡 × 「全局 3 卡约定」与窄屏断点

- 5 组 × 3 卡是当前**全局统一的设计语言**（实测 4 组均 3 卡）。货币流动性扩到 5 卡后，
  该组与其他 4 组的**卡数不再一致** —— 这是**产品取向决策**，原文档已标为待拍板项 ✓（评估：标注得当）。
- **窄屏断点**（`.ao-cards` → 2 列 / 1 列）下，5 张卡会变 **3 行（2+2+1）**，末行残缺。
  建议在窄屏让最后一张 `grid-column: span 2`（跨满）以避免残缺行 —— **这是原文档未覆盖的响应式问题**。

### K3｜R2/R4 需要「每环一句结论」，但后端只有 3 条 `verdicts`

R2 要求「四环各有结论条」、R4 要求横向对比叙事 ⇒ 后端需**新增**「银行间定价 / 信用派生 / 对外与资产」的判读文案

⇒ **R2 的因果链不止前端模板**：`registry.py` 的 `question_text` / `desc` / `desc` 声明也要按四环重写

## 六、🟡 工程风险与验收陷阱（3 项，原文档未覆盖）

### E1｜`@ttl_cache(600)` 会让「改完不重启」的验收变成假信号

实码：`money_cost.py:1412` → `@ttl_cache(600)`；`_cache.py` 为**进程内**缓存，key = `(args, kwargs)`（含 `as_of`/`trend_days`，**参数隔离正确，无污染 bug** ✓）。

**风险**：R3 新增 `card_kpis` 字段后，若**未重启后端**直接验收，10 分钟内仍返回旧结构 ⇒
前端拿不到新字段 ⇒ 触发静默回退 ⇒ **表现为「卡片内容错」，极易被误判为「前端写错了」**。

**要求**：改造清单必须写明「**API 结构改动 → 必须重启后端 + 清缓存后再验收**」，且验收脚本**先断言字段存在**（`card_kpis` 必须 `is not None`），再断言内容 —— 防止「回退路径」冒充成功。

### E2｜回放模式（`is_replay`）与新增读数的一致性未定义

接口支持 `as_of` 历史回放（`is_replay` 字段）。而新增读数里有**季度（BIS）/ 月（M2、外储）/ 周（美联储）** 三种频率。
**回放某个交易日时，新月度/季度数据应取「该日及之前最近一期」** —— 这是必须确认的行为，
否则回放视图会把「未来数据」混进历史（`_cn_reserve` 等已有过滤逻辑，但 R2 重排后需复核）。

### E3｜验收判据不要写死像素（评估文档本身的改进）

主文档 R1 判据写 `结论区 top < 1120`。1120 是当时探针的视口高，**换屏幕即失效**。
⇒ 应改为**相对量**：`top < viewportHeight` 或 `top < 0.9 × viewportHeight`，并在验收脚本里**从 `page.viewport()` 取值**。
