## 一、背景与目标

### 1.1 背景

2026-09-26 上一轮已落地「货币总量」分区（`mc-quantity`，7 个 KPI、2839px）。落地后复核发现：**信息架构层面的问题比排版问题更严重**。

### 1.2 问题定性（金融视角）

货币流动性在金融学上**不是一堆平行指标，而是一条单向传导链**：

```
① 央行操作  →  ② 银行间定价  →  ③ 信用派生  →  ④ 对外与资产
（政策与投放）  （资金价格）      （货币存量）     （边界条件）
```

而现页的 5 个切面是**三种不同分类轴的混装**：

| 切面 | 实际属于哪个轴 | 问题 |
|---|---|---|
| 价格 | **维度轴**（钱的贵贱） | 与「数量」互补，但被拆到不同层 |
| 数量 | **维度轴**（钱的多少） | 内容横跨 ①③④ 三环，是个大杂烩 |
| 预期 | **机理轴**（市场定价） | 与「价格」实为同一环，却并列成两个切面 |
| 政策 | **机理轴**（央行姿态） | 属 ① 环 |
| 外部约束 | **边界轴**（外生给定） | 属 ④ 环 |

> **三个轴混在一层 ⇒ 必然重叠、遗漏、不可比。** 这是「看着乱」的结构性来源，不是排版问题。

**一个反讽的实证**：项目契约⑩早就写对了原则 ——「**领域边界按因果位置划，不按数据源划**」（`registry.py` 第 102 行）。但这条**只被用来划「模块之间」的边界**（本模块 vs 资金温度），**没有被用来划「页内区块」**。所以 `mc-quantity` 是按**数据表**划出来的：

| 数据表 | 块 | 实际所属环节 |
|---|---|---|
| `global_liquidity_bis` | 全球层 | ④ 对外与资产 |
| `us_fed_balance_weekly` + `us_money_market_daily` | 美国层（美联储三腿） | **① 央行操作** |
| `us_money_supply_monthly` | 美国层（M2） | **③ 信用派生** |
| `eu_money_supply_monthly` | 欧元区层 | **③ 信用派生** |
| `cn_liquidity_monthly` | 中国层（M2） | **③ 信用派生** |
| `cn_reserve_monthly` | 中国层（外储/黄金） | **④ 对外与资产** |
| `cn_omo_daily` | 中国层（OMO） | **① 央行操作** |

⇒ **一个 `mc-quantity` 块横跨 ①③④ 三环，而 ③ 信用派生反而没有独立分析单元。**

### 1.3 目标

| 编号 | 目标 | 判据 |
|---|---|---|
| G1 | 结论先行 | 用户**不滚动**即可看到「现在钱松还是紧」的结论 |
| G2 | 切面全覆盖 | 每个切面（含数量、外部约束）在**卡片墙有一张卡** |
| G3 | 按因果位置分区 | 详情页区块 = 四环传导链，一目了然 |
| G4 | 消除孤立读数 | M2 不再孤立（改为美/欧/中横向对比） |
| G5 | 页面体量可控 | 首屏可见结论；低频明细默认折叠 |

#### R1｜结论条上移（结论先行）🔴

**现象**：全局判读条 `mc-cross` 位于第 5.2 屏（y=5830），用户需滚动 5 屏才看到答案。

**根因**：模板按「数据获取顺序」排布（参数 → KPI → 曲线 → 时序 → 政策 → 外部 → 数量 → 结论），结论被最后写入因此排最后；未按「阅读顺序」重排。

**修法**（推荐方案 A）：

- **A（推荐）** 在参数区之后、KPI 之前，新增一条**轻量结论条** `#mc-verdict`；其内容从现有 `policyMarket` + `equityCross` 两个数据源生成，**复用后端已下发的 `reading.headline` / `reading.detail` / `reading.tone`**，前端不新增结论句。
  - 原 `mc-cross` 区块**保留在页尾**作为详版（含两份 reading 全文）——避免信息丢失。
  - ⚠️ 若嫌重复，可将页尾 `mc-cross` 降级为「两个 reading 的并排明细」，去掉与页头重复的 headline。
- B 直接把整个 `mc-cross` NCard 移到页头 —— **不推荐**：NCard 有标题+边框，体量重，会挤压首屏。
- C 不动。

**约束**：
- 🔴 结论句必须**由后端生成**（契约①：前端拼结论句会产生第二份口径）。若需新文案，请在 `money_cost.py` 里新增 `headline` 字段，**不要在前端拼**。
- 🔴 `detail` 内若含 `**`，必须走 `RichText` 渲染（契约⑥ / 交互规范 §14）。

**验收**：
- [ ] 首屏（不滚动）可见结论条，且 `headline` 非空
- [ ] 结论条 `tone` 三态样式与后端一致（`loose`→金 / `tight`→琥珀 / `mixed`→蓝）
- [ ] 页尾 `mc-cross` 仍在（未丢失详版）
- [ ] 页内 `**` 原样出现次数 = **0**（DOM 量测）

#### R2｜卡片墙补「数量」卡 🔴

**现象**：上轮落地的 7 个数量读数（BIS 境外美元信贷 14.75 万亿 / 美元净流动性 A5 5.80 万亿 / 美国 M2 23.34 / 欧元区 M3 20.00 / 中国 M2 52.87 / 外储 3.44 万亿 / 黄金增持 22 月）在总览页**零曝光**。

**根因**：`money_cost.py` 第 1606-1607 行注释明写「**不标 `card_rank`** —— 存量低频读数不该顶卡片墙（D1=A「不拆大卡」）」。但是**机制上完全支持**（契约②：`full` 档可放 6 个读数）—— 这是**当时的设计选择，不是技术限制**。

**修法**：

1. `backend/app/analysis/registry.py`：在货币流动性组新增 1 张 track 卡（建议**插在现有三卡之后**）：

```python
{
    "module_id": "money-cost-quantity",
    "name": "数量",
    "group": "货币流动性",
    "kind": "track",
    "icon": "💧",
    "desc": "境外美元信贷、美元净流动性、美/欧/中货币存量",
    "question_text": "钱够不够（水位）",
    "data": "money-cost",          # 🔴 必须复用同一端点（契约⑦），否则多一次往返
    "question": "q4",              # 🔴 必须新增 q4，否则撞「静默回退」陷阱
    "card_span": "full",           # 6 个读数 ⇒ full（12 列，独占一行）
    "detail": "/analysis/money-cost",
},
```

2. `backend/app/analysis/money_cost.py`：给要上墙的数量 KPI 补 `card_rank` + `questions`：

```python
# 在 _quantity_state() 组装 items 时，挑 6 个最能代表「水位」的，按重要性排 card_rank
# 建议次序（金融重要性）：A5 美元净流动性 → BIS 境外美元信贷 → 中国 M2 → 美国 M2
#                       → 欧元区 M3 → 中国外储
```

3. `backend/app/analysis/money_cost.py`：新增 `verdicts["q4"]` —— 数量维度的子判读（**复用现有 `_quantity_verdict()` 的产出，零额外查询**）。
4. `backend/app/analysis/money_cost.py`：新增响应字段 `card_kpis`（见 §五 关键设计）。

**🔴 三个必须避开的陷阱**：

| 陷阱 | 后果 | 规避 |
|---|---|---|
| **T1｜`questions` 未标** | `scoped` 为空 ⇒ 回退全量 `kpis` ⇒ **数量卡上显示价格读数**（静默错误，不报错） | 每个要上墙的数量 KPI 必须标 `questions: ["q4"]` |
| **T2｜只标了 `card_rank` 没标全** | 契约②：只要有 1 个标了 `card_rank`，**同卡未标的论据被整体丢弃** | 要上墙的 6 个全标；不要上墙的**一个都别标** |
| **T3｜只读 `r.kpis`** | `quantity_kpis` 是独立数组，卡片墙**根本不读** ⇒ 卡是空的 | 走 §五 的 `card_kpis` 方案 |

**验收**：
- [ ] 总览页货币流动性组出现「数量」卡，且**独占一行**（full）
- [ ] 卡上 6 个读数**全部非 `--`**，且与详情页数值**逐位一致**
- [ ] 卡上读数是**数量侧**的（14.75 / 5.80 / 23.34 / 20.00 / 52.87 / 3.44），**不是** Shibor 等价格侧数字（验证 T1）
- [ ] 卡片判读条 = 后端 `verdicts.q4.headline`，**不是** `q1` 的（验证 T1）
- [ ] 单位后缀统一为「 万亿美元」，且**无 `scale` 刻度条**（契约⑤：存量水平不做分位，见设计文档纪律 8）

#### R3｜卡片墙补「外部约束」卡 🟠

**现象**：`mc-external`（美债曲线 / 中美利差 / 美元指数 / 全球央行方向）在总览页零曝光，占详情页 19% 体量却无入口。

**根因**：同 R2 —— `external_kpis`（`money_cost.py:1603`）是独立数组，且文档明写「不标 `card_rank`，卡片墙仍是 3 张 track 卡」。

**修法**：

1. `registry.py` 新增 track 卡 `money-cost-external`，`question: "q5"`，`card_span: "narrow"`（1 个读数，建议选**中美 10Y 利差**或**美元指数**——最能代表「外部闸门」的一个）。
2. `money_cost.py`：该 KPI 标 `card_rank: 1` + `questions: ["q5"]`；新增 `verdicts["q5"]`（复用 `_external_state()` 的 `reading`）。
3. 并入 `card_kpis`。

**验收**：
- [ ] 总览页出现「外部约束」卡，读数非 `--`，与详情页 `mc-external` 一致
- [ ] 判读条 = `verdicts.q5.headline`
- [ ] 卡片墙货币流动性组**布局不缺角**（见下方列数计算）

**📐 列数计算（5 张卡的布局，必读）**

栅格 `--ao-cols` = 组内 span 之和，`narrow=3 / half=4 / full=12`：

| 方案 | 卡片组合 | span 和 | 渲染结果 | 评价 |
|---|---|---|---|---|
| **α（推荐）** | 3 narrow（现有）+ 1 **narrow**（外部约束）+ 1 **full**（数量） | 3+3+3+3+12 = **24** | 第一行 4 narrow（12）✓ 第二行 1 full（12）✓ | ✅ **两行满格，无留白** |
| β | 3 narrow + 1 **half**（外部约束）+ 1 **full**（数量） | 3+3+3+4+12 = **25** | 第一行 3+3+3+4=13，剩 12 ⇒ 第二行 full ✓ | ⚠️ 第一行末尾余 12 列但 full 放不下 ⇒ 实际两行，勉强 |
| γ | 3 narrow + 2 **half** | 3+3+3+4+4 = 17 | 第一行 13，第二行仅 4 列 | ❌ 第二行严重留白 |
| δ | 5 张全 narrow | 15 | 一行 5 张（每张 1/5 宽） | ⚠️ 数量卡只有 1 个读数，浪费 |

> **执行建议**：按 **α** 落地 —— `数量` 用 `full`（6 读数），`外部约束` 用 `narrow`（1 读数）。若希望外部约束展示 3 个读数，改用 `half` 并接受方案 β 的轻微不齐。

⚠️ 注意 `@media (max-width: 1200px)` 会把所有卡压成 1 列（`:522-525`），请在 **≥1200px** 视口验收布局。

#### R4｜页头 desc 瘦身 + 切面锚点导航 🟠

**现象**：
- desc 是约 150 字功能清单（把 5 切面 + 6 子项全列出来），像说明书，不像「这页回答什么」（违反契约③：desc 不写功能清单、不写会漂移的计数）。
- 5.5 屏的页面**无任何页内导航**，想直达「货币总量」只能滚 3 屏。

**根因**：desc 随每次新增数据源不断追加枚举；页头容器 `AnalysisModuleView.vue` 没有锚点能力。

**修法**：

1. `registry.py`：把 `money-cost` detail 模块的 `desc` 改为**一句话**：

### 5.2 [❌ 原指引已作废 · 见勘误] 滚动定位（R4 锚点导航）

> ## ❌ 勘误（2026-09-26 实机量测推翻，证据见《需求评估报告_全栈开发视角》§三 B2）
>
> **原文写「`element.scrollIntoView()` 对它无效 —— 必须直接改 `scrollTop`」，该结论错误。**
>
> **实测证据**（`_scratch/_probe_scroll_who.js`，两轮交叉验证）：
> ```
> 点击前  #mc-qty-global top = 3632   容器 scrollTop = 0
> 点击后  #mc-qty-global top = 0      容器 scrollTop = 3632   window.scrollY = 0
> 滚动主体：div.n-layout-scroll-container（唯一变化者）；页面错误 0
> ```
> ⇒ **`scrollIntoView({behavior:'smooth', block:'start'})` 完全有效**，且配套的
> `scroll-margin-top: 12px` 同样生效（目标最终停在 top∈[0,40] 补偿区间）。
> 该实现**已在生产使用**：`KpiCards.vue:81` 的 `goAnchor()` 就是它，
> 且 **5 个详情页全部配了** `scroll-margin-top: 12px`
> （`MarketWindView.vue:327` 注释原文：「KPI 卡点击滚到锚点时留出顶栏高度，避免卡片标题被顶栏遮住」）。
>
> **若照下文改为直接改 `scrollTop`，会**：① 丢掉 `scroll-margin-top` 补偿 ⇒ 目标标题被顶栏遮住；
> ② 与其余 4 个详情页实现分叉。**属反向劣化。**
>
> **✅ 修正后做法**：**直接复用现有 `goAnchor()` 的同一模式** ——
> `el.scrollIntoView({ behavior: 'smooth', block: 'start' })` + 目标元素加 `scroll-margin-top: 12px`。
> 另：`goAnchor` 用的是 `getElementById(k.anchor)?.…`，**id 不存在时静默跳过、零报错**
> ⇒ R2 改区块 id 必须同步后端 12 处 `anchor`（详见评估报告 §四 C3）。
>
> ⚠️ 教训：**把一次特定场景的观察泛化成「普遍无效」是危险的** ——
> 该结论当时未做**负对照**（未验证同一个 `scrollIntoView` 在正常路径下是否有效）。

```ts
// ❌ 以下为原指引（已作废，保留供追溯）—— 请勿按此实现
// ⚠️ naive-ui 的滚动宿主是 .n-layout-scroll-container，不是 window/body
//    element.scrollIntoView() 对它无效 —— 必须直接改 scrollTop
function scrollToSection(id: string) {
  const el = document.getElementById(id)
  if (!el) return
  const host = document.querySelector('.n-layout-scroll-container')
  if (host instanceof HTMLElement) {
    const top = el.getBoundingClientRect().top
       + host.scrollTop
       - host.getBoundingClientRect().top
       - 12                       // 留 12px 呼吸间距
    host.scrollTo({ top, behavior: 'smooth' })
  } else {
    el.scrollIntoView({ behavior: 'smooth', block: 'start' })
  }
}
```

> ⚠️ 原注「本坑已实测确认（2026-09-26 DOM 量测脚本踩到）」为**误判**（见上方勘误）。

## 附录 A｜本次需求的金融依据

**为什么「四环传导链」是正确的切分？**

| 环节 | 金融含义 | 回答的问题 |
|---|---|---|
| ① 央行操作 | 基础货币的**投放动作** | 央行在做什么？ |
| ② 银行间定价 | 资金在**金融体系内**的价格 | 钱现在贵不贵？ |
| ③ 信用派生 | 基础货币被**派生为广义货币** | 钱最终有多少？ |
| ④ 对外与资产 | 全球**边界条件**（汇率、海外利率、离岸美元） | 外部约束有多紧？ |

**判据一句话**（契约⑩）：这个读数是「资金价格/数量的**给定条件**」（→ 因），还是「资金行为的**结果**」（→ 果）？本模块管因（①~④ 全是给定条件）；果归「资金温度」模块。

**为什么卡片不能「各自为政」？**

流动性指标的专业价值**恰在交叉验证**：
- 单看「价格低」→ 不知是宽松，还是**需求萎缩**
- 单看「M2 涨」→ 不知是主动宽松，还是**被动派生**
- 单看「美联储缩表」→ 不知对 A 股是收紧，还是**外资流入**

⇒ 正确形态是「**分卡独立推理 + 一张合并结论**」，缺一不可。现状两头都缺（分卡只有 1 个读数、合并结论在第 5.2 屏）——这正是 R1 + R2 要解决的事。
