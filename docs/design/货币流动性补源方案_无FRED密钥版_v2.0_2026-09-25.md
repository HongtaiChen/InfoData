> **FRED 拿不到 Key，对本方案的实际影响接近于零——因为它本来就不该是主干。**

## 3. ⭐ 全球层的新答案：BIS 全球流动性指标（GLI）

v1.0 §4 把「全球央行资产合计」标为「🟡 可拼，但要写 3 个解析器」。**本轮找到了更权威、更省事的替代**：

```
GET https://stats.bis.org/api/v1/data/BIS,WS_GLI,1.0/Q.USD?format=csv&startPeriod=1990
→ 200 / CSV（实测 6,720 行，2000-03-31 ~ 2026-03-31，19 个借款人码）
列：FREQ, CURR_DENOM, BORROWERS_CTY, BORROWERS_SECTOR, LENDERS_SECTOR,
    L_POS_TYPE, L_INSTR, UNIT_MEASURE, TITLE, UNIT_MULT, DECIMALS,
    COLLECTION, AVAILABILITY, TIME_PERIOD, OBS_VALUE, OBS_STATUS, ...
```

> 🔴 **勘误（2026-09-26 落地时实测，推翻本文原结论）**：本文原写「`/all` 全量形式 **200 可用**；
> 按维度过滤的 key 写法待定」—— **实测恰好相反**：
> - `/all?format=csv&startPeriod=...` → **404**
> - `/Q.USD`（**只给 3 段 key**）→ **200**，返回正确 CSV
>
> ⇒ 有效形式是 **`FREQ.CURR_DENOM.BORROWERS_CTY`（3 段）**，在 `Q.USD` 之后再追加任何维度即 **404**
> （实测 `Q.USD.US.N`、`Q.USD.US.N.A` 全 404）。
> ⇒ 落地做法：用 `Q.USD` 一次拿全「美元计价的全球信贷」，再按 7 个维度在库里区分。

> ⚠️ **格式坑（实测）**：resource key 的 provider/dataset/version **必须用逗号分隔**
> `BIS,WS_GLI,1.0`；斜杠形式 `BIS/WS_GLI/1.0` 一律 **404**（v1.0 那次 404 就是这个原因）。

#### 3.1 🔴 维度语义与「唯一正确取数口径」（落地时实测，**这是本表最容易错的地方**）

从 BIS 官方数据门户的系列页读出 8 维完整定义（`data.bis.org` 的 Series key `Q.USD.3P.N.A.I.B.771`）：

| 维度 | 取值 | 语义（官方原文） |
|---|---|---|
| `BORROWERS_CTY` | **`3P`** | **All countries excluding residents**（全体非美借款人**合计**） |
| | `US` / `CN` / `MX` … | 个别经济体（本库明细**只有 13 个新兴市场**，**无欧元区/日本/英国**） |
| `BORROWERS_SECTOR` | `N` | Non-banks, total（非银行部门，**这是 GLI 的主口径**） |
| | `G` / `P` | Government / Private non-financial（仅在 `I` 之外出现） |
| `LENDERS_SECTOR` | `A` | All sectors（全体贷款方） |
| `L_POS_TYPE` | **`I`** | **Cross-border & Local in FCY**（跨境 **+ 借款人本地外币**——比"跨境"更宽） |
| | `A` | 境内（对美借款人的美元信贷） |
| `L_INSTR` | **`B`** | **Credit (loans & debt securities)** = 贷款&amp;债券**合计** |
| | `D` / `G` | 只 IDS 债券 / 只银行贷款（**均为 `B` 的子项**） |
| `UNIT_MEASURE` | `USD` | **百万美元（存量）** |
| | `771` | **Year-on-year changes, in per cent**（**同比增速 %**，官方已算好） |

> 🔴 **三重重复陷阱 —— 三个条件缺一个就静默算错**：
> 1. `l_instr` 的 **`B` 已包含 `D` 与 `G`** ⇒ B+D+G 相加是**重复**。
>    实测 `3P` 下 `D+G = 8.0646 + 6.683 = 14.7476` ≈ `B = 14.7477`（**逐位吻合**，铁证）。
> 2. 聚合码 `3P`（全体非美合计）与各国明细**并存** ⇒ 相加是**重复**。
> 3. `unit_measure='771'` 是**同比 %**，混进金额求和无意义。
>
> **唯一正确口径**（离岸美元 / 全球美元信贷）：
> ```
> WHERE borrowers_cty='3P' AND borrowers_sector='N' AND lenders_sector='A'
>   AND l_pos_type='I' AND l_instr='B' AND unit_measure='USD'
> ⇒ 14,747,700 百万美元 = 14.75 万亿美元 @2026-Q1
> ```
> **对照 BIS 官方公布值（四期逐位吻合）**：
>
> | 期 | 本库 `3P+B` | BIS 官方 | 本库 yoy(`771`) | 官方 yoy |
> |---|---|---|---|---|
> | 2025-Q1 | 13.7359 万亿 | $13.7T | 5.159% | 5% |
> | 2025-Q3 | 14.2264 万亿 | $14T | 7.260% | 7% |
> | 2025-Q4 | 14.2539 万亿 | $14.3T | 8.444% | 8.5% |
> | 2026-Q1 | **14.7477 万亿** | — | 7.298% | — |
>
> ❌ **错口径**（`borrowers_cty<>'US'` 全量 `SUM(obs_value)`）= **45,951,383 百万 = 真值 3.12 倍**。
> 这个错值曾误写进本文 §2.1/§3、分析层设计文档 §二、采集器旧 note、`table_meta.flow_desc`，
> 已于 2026-09-26 全部勘误。
>
> ⭐ **意外收获**：`unit_measure='771'` 是 BIS **官方算好的同比增速**，可直接用（免自算季度同比、
> 避开季节性陷阱），是一个免费的派生数据列。


**为什么它比「自建全球 M2 汇总」更好**：

| | BIS GLI | 自建全球 M2 汇总 |
|---|---|---|
| 口径 | **官方**，BIS 定义并发布 | 合成，非官方 |
| 核心维度 | **`CURR_DENOM`（计价货币）× `BORROWERS_CTY`（借款人国）** | 只有「各国本币 M2」 |
| 能否回答「离岸美元有多少」 | ✅ **能**（`CURR_DENOM=USD` × 非美借款人） | ❌ 不能 |
| 维护成本 | 一个采集器 | 需拼 N 国 × 汇率换算 |

> ⇒ **全球层落点改为 BIS GLI**。「全球 M2 单一总量」这个目标本身要**降级**：
> 免费无官方源（见 §4），应改为「**BIS 全球流动性总量** 作代理 + 主要经济体 M2 分列」，
> 而不是追求一个不存在的「全球 M2 单一数字」。

## 4. ⚠️ 本轮实测出的三个「坑」（必须写进方案，否则会静默出错）

### 4.1 🔴 FED/H41 里有 `-999999.0` 缺失哨兵

| 类别 | 哨兵情况 | 处置 |
|---|---|---|
| 核心汇总序列（`RESPPMA_N.WW` 总资产、`RESPPALGASMO_XAW_N.WW` MBS 等） | **0 / 1241** ✅ 干净 | 直接用 |
| 已停报细分子项（`RESPPALGAO_F01`~`_F12`、`RESPPALGASMO_F01`~`_F12`） | **341 / 1241** ❌ | **必须过滤 `-999999`** |

> `-999999` 是「本项未报」的哨兵，不是数值。**若直接入库，会被当成 −10 亿级真实读数**，
> 且因为它是**大负数**，在「同比/环比」里会产生极端异常值。
> ⇒ 采集器必须显式剔除，并在 `DQ` 里加一条「哨兵计数 = 0」的守护。

### 4.2 🟠 DBnomics 镜像的 IMF/IFS **不完整**，不能当「全球 M2」用

| 查询 | 实测 |
|---|---|
| `series/IMF/IFS?q=United States Broad Money` | ❌ **num_found = 0** |
| `series/IMF/IFS?q=United Kingdom Broad Money` | ❌ **num_found = 0** |
| `series/IMF/IFS?q=Euro area Broad Money` | ❌ **num_found = 0** |
| `IMF/IFS/M.JP.FMB_XDC`（日本） | ✅ 279 期，止 **2025-02** |
| `IMF/IFS/M.BR.FMB_XDC`（巴西） | ✅ 283 期，止 2025-06 |
| `IMF/IFS/M.KR.FMB_XDC`（韩国） | ✅ 281 期，止 2025-04 |

> ⇒ IMF/IFS 镜像**主要经济体缺失 + 滞后约 1.5 年**。**不要用它兜全球层**（这正是 §3 改用 BIS GLI 的原因）。
> 小国/边缘国家可用，但须逐国验证 —— 本主题不依赖它。

## 9. 方法论小结（本轮新增）

| 教训 | 实例 | 正确做法 |
|---|---|---|
| **「上游下架」是新的失败形态** | DBnomics 的 FRED 镜像被移除 | 依赖第三方镜像时，**必须同时记录上游下架风险 + 备选上游** |
| **同一机构的多个服务域，可达性可以完全不同** | ECB 三域全断，但 DBnomics 侧完全可用 | 别因「机构直连不通」就判死，**找镜像/聚合层** |
| **第三方镜像的「不完整」必须逐项验** | IMF/IFS 镜像缺美/英/欧 | 拿到「XX 数据集存在」≠「我要的那条序列存在」，**必须实取目标序列** |
| **哨兵值（`-999999`）比缺值更危险** | FED/H41 停报子项 | 缺值一般是 `NULL`（可被 SQL 自然过滤）；**哨兵是合法数字**，会污染统计且不报错 |
| **API 的 resource key 形态要试** | BIS `BIS,WS_GLI,1.0` ✅ vs `BIS/WS_GLI/1.0` ❌ | 一次 404 不代表资源不存在，**先试另一种分隔符** |

#### 11.3.5 双口径关系（实测：**不能按市价互校**，这是本节最重要的结论）

把「人民币表内口径」与「官方美元口径」相除，得到**隐含折算率**（实测 24 期）：

| 月份 | `cn_cb_balance.fx_reserve`（亿元） | `ak 外储`（亿美元） | 隐含折算率 |
|---|---|---|---|
| 2024-06 | 221,899.72 | 32,223.58 | **6.886** |
| 2024-09 | 220,966.47 | 33,163.67 | 6.663 |
| 2025-06 | 215,804.96 | 33,174.22 | 6.505 |
| 2026-02 | 213,763.92 | 34,278.07 | 6.236 |
| **2026-08** | **217,247.55** | **34,383.25** | **6.318** |

**结论三条**：
1. 折算率**单调下行**（6.886 → 6.318，24 期 −8.2%），**不等于当期市场汇率**（同期市场汇率约 7.0~7.3）
   ⇒ 它是**历史成本 / 复合折算**口径，**不是汇率**。
2. ⇒ **禁止用市场汇率做严格互校**（如「偏差 > 1% 即告警」这类规则会**稳定误报**）。
3. ⇒ 可行的软校验只有：**区间守护 `[6.0, 7.4]`** + **月度变动绝对值 < 2%**。
   黄金同理：`monetary_gold(亿元) / gold_reserve_oz(万盎司)` 实测 0.5759 → 0.6834（即 ≈5,759 → 6,834 元/盎司），
   同为**历史成本**（远低于市价），**同样不可按市价互校**。

> ⚠️ **实现方式**：该互校**跨两张表**，而本库 DQ 检查器是**单表 + where** 结构（无 JOIN）
> ⇒ 互校**放在采集器内的断言 + 日志**（与美国层「官网 ⟷ DBnomics 双轨」同套路），
> **不要试图写成 DQ 规则**。
